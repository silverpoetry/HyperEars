# Apple AAP 开发记录

## 当前范围

本分支已接入小米原生优先、明确放弃本次连接时由 HyperEars 补位的 Apple 候选路径。
注册表默认仍保留 Apple；只有会话管理器取得当前连接的可信原生拒绝结果，并确认标准
耳机身份及 AAP 服务 UUID 后，才创建私有会话。协议层提供电量及四态聆听控制。
完整型号覆盖、高级功能和实机验证仍在实施；当前检查结果不代表 AirPods 5 已完成实机适配。
原生准入方案见[连接计划](superpowers/plans/2026-10-28-apple-native-admission.md)。

## 协议与来源

目前沿用已有 AAP Classic L2CAP PSM `0x1001`、握手、通知订阅和严格电量解析。
聆听状态为 `04 00 04 00 09 00 0D <mode> 00 00 00`：
`1` 关闭、`2` 降噪、`3` 通透、`4` 自适应。写入使用同一控制格式。
AndPods 4.3.8 的聆听定义作为首要参考，HyperPods-X `018765be` 和原始 HyperPods
交叉核对；本轮独立表达协议事实，没有复制闭源应用代码或产品素材。

## 设备信息与型号候选

设备信息 `0x001d` 按偏移 7 的无符号小端长度读取，完整帧长为 `9 + length`，
不能在其二进制内容中搜索下一帧。偏移 11 开始的十一段 NUL 字符串保留空字段，
随后跳过两段各 17 字节的不透明标识，再验证两段 NUL 字符串及精确结尾。
所有字符串严格验证 UTF-8；仅投影型号和活动固件版本，各限 128 个 UTF-16 码元，
不截断型号、不传播名称、序列号、不透明标识和配对时间。待解析缓冲按协议的 16 位
长度上限分批处理。未明头字段不施加猜测的版本限制。

自适应型号候选来自固定版本 LibrePods 声明，并以 AndPods 的专用型号字段解析为前提：

- AirPods 4 ANC：A3056 / A3055 / A3057。
- AirPods 5：A3531 / A3532 / A3533；无线充电盒版：A3439 / A3440 / A3441。
- AirPods Pro 2 Lightning：A2931 / A2699 / A2698；USB-C：A3047 / A3048 / A3049。
- AirPods Pro 3：A3063 / A3064 / A3065。

这些是控制范围候选，不是小米原生支持名单，也不是本项目的型号实测清单。
未知型号仍可依据实际自适应回报开放该模式。Max、Beats 等型号的完整能力映射继续跟踪。
证据与实施边界见[设备信息审查](research/source-audits/apple-device-identity-followup.md)。

## 状态与控制约束

- `apple.listening_mode` 保存真实四态及本会话允许的选项；旧三态兼容投影仍将自适应
  映射到 ANC，但原生扩展卡片必须使用 Apple 专属状态识别实际选项。
- 合法聆听回报开放基础三态。自适应由本会话的实际自适应回报确认，或由严格解析的
  已知自适应型号与同会话合法聆听回报共同确认；两种报文的到达顺序不限。
  型号变为未知时撤销仅由型号推断的选项；实际自适应回报的证据保留至协议重置。
  设备名称、型号信息单独到达及固件字符串均不开放控制。
- 只有电量回报、无效模式或初始匹配均不开放聆听控制。
- `apple.set_listening_mode` 经过现有控制请求合同校验，写入后订阅通知等待设备回报；
  写入成功不直接改变已确认状态。标准噪声请求也采用设备回报确认。
- 卡片绑定沿用 `MiLinkCardAdapter` 注册与生命周期，不直接访问蓝牙通道。
  original/select-card 两种布局均使用真实宿主条目类；前三项保留通透／降噪／关闭和原生
  图标，第四项自适应只在支持集合内显示。点击重新校验最新状态，选中态只跟随设备回报。
  控件替换辅助类与 FloS2 共用，构造失败不修改宿主，解绑恢复原控件。

## 验证边界

原生判定观察实际连接调用，保留小米的原始结果与异常。通知携带生产者、物理连接、查询
代次和递增版本；旧回复、未知状态及读取错误均不授权私有连接。正常 HFP 决策先于 A2DP、
以及 HFP 保持连接时的 A2DP 重连均有回归覆盖。仅媒体／无 HFP，或 Hook 安装前原生决策
已结束且没有后续真实决策的情况，暂时保持标准蓝牙。启动时机和真实 Hook 仍需设备验证。

MiLink 展示归属也按同一生产者和物理连接隔离：新连接重新查询原生展示准入，同一物理
连接内的逻辑会话替换保留有效原生优先结果。旧的无连接标识通知不再隐藏新连接的模块
卡片；协议通道许可本身仍不直接授予展示许可。Standard 回退也携带该连接归属信息。

集成测试覆盖真实自适应状态、请求门禁、序列化、重置及写入后状态不抢先改变。
编解码测试覆盖四种值的全部分片边界、所有无效单字节模式、下一帧恢复及半帧重置。
实际通知回读、完整原生卡片、各型号固件差异和小米接管优先顺序仍需最终实机验证。
