# 耳机语音播报

在 HyperEars 的“系统提示”设置中选择“耳机语音播报”。默认**关闭**，“连接播报”和
“低电量播报”也分别默认关闭。开启后可选择始终按事件播报或仅“屏幕关闭时”播报；
后者判断屏幕是否处于交互状态，不等同于仅锁屏。两套应用界面使用相同设置。

连接播报在新物理连接的前10秒内，获得有效准入和输出路由后，最多说一次“耳机已连接”。
低电量播报在新报告中出现未充电耳机低于20%的电量时，每次连接最多提醒一次。
0% 是有效低电量；未知值不会变成0，充电盒不会触发提示。真实左右耳分别识别，系统
整体电量不会被重复读成左右耳。同一事件同时满足连接与低电量时合为一句。

播报音量默认50%，可选25／50／75／100%，仅作为当前媒体音量的相对倍率，不更改系统
音量。仅当媒体输出和提示音输出均精确指向当前耳机、HyperEars仍管理该设备且没有通话
时尝试播报。系统静音／振动、媒体静音或0音量、任何勿扰模式都会跳过，不绕过系统限制。
输出不明确、其他播报仍进行中或引擎／语言／音频焦点不可用时也会跳过，不事后补播。

禁用设置、断开、取消配对、会话更换、控制权交接、系统接管、producer死亡、音频路由
改变、通话或对话开始会停止当前播报。等待初始化时，如果已提醒的低电量耳机恢复至
20%以上、开始充电或读数失效，也会取消提示。重复报告、运动数据和状态回放不会产生
声音。中途修改设置不会立即读出已有状态；已处于低电量的历史快照不会在启动时播报。

实现沿用现有 `com.xiaomi.bluetooth` 原生宿主和认证状态，不打开新的协议连接，不增加
作用域、轮询、常驻引擎、服务或通知读取权限。每次提示才创建系统 TTS 实例，使用中文
语音及导航提示／语音属性，申请不延迟的短暂音频焦点。初始化至播报结束最长10秒；
结束、失败或取消后停止并销毁该实例、释放焦点和所有观察回调。系统引擎需在宿主内可用，
没有可用引擎／中文语音时不会发起安装、下载或权限操作。

## 来源与验证边界

AndPods4.3.8 本地研究提供默认设置与功能参考：`entity/TTSConfig.java`、
`entity/TTSSwitchEnum.java`、`service/BackgroundService.java:441–450,549,1193–1209`、
`util/TTSSpeaker.java`。源实现首个高电量样本也会消耗提醒机会，且排除0；本实现改为
基于可信电量变化的首次低电量提醒，并保留0%的意义。没有复制代码或资源，没有加入
应用消息朗读、自定义问候或通用语音助手。

Android35 本地 SDK 源码确认 TTS 的销毁与引擎可见性要求，导航提示使用媒体音量流，
短暂音频焦点支持拒绝延迟授予。测试涵盖阈值／拓扑、回放／去重、设置基线、低电量恢复、
同步初始化、迟到回调隔离、焦点拒绝和重入丢失、10秒截止、真实路由／静音／勿扰与清理。
TTS `speak` 返回成功仅证明请求已入队，不证明耳机实际发声；构建测试和实机听感验收分开记录。
