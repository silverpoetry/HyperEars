# 连接媒体音量

在 HyperEars 设置的“系统提示”中选择“连接媒体音量”。默认**关闭**，可选 0%（系统最低音量）或
10% 至100% 的预设值。两套应用界面使用相同的设置与 RemotePreferences 同步路径。

设置用于**下次物理连接**，不会立即修改已连接耳机的音量。耳机连接后的10秒内，只有
原生宿主确认媒体实际输出到该耳机、HyperEars仍拥有控制权且不在通话中时，才会应用
一次媒体音量。系统仍决定实际音量档位与限制；不改变铃声／通知音量，不启动播放，
不请求音频焦点，也不改音频路由。断开后不恢复旧音量。

等待过程中观察到媒体音量改变、设置改变、设备断开／取消配对、通话、会话更换、控制权
交接、系统接管或 Apple 对话开始会取消本次机会。10秒内无法确认输出路由也会结束等待。
即使后续状态重复或路由回来，同一次物理连接也不会再次应用。模块／宿主重启后的状态
快照不会被当成新连接。路由切换使系统恢复了不同媒体音量时，也保守取消，而不覆盖它。

实现复用已启用的 `com.xiaomi.bluetooth` 原生展示宿主，不增加作用域、前台服务、轮询或
权限。回调只在这一次有界等待期间注册；结束后撤销。最多保存128个地址的内存连接
去重记录，达到上限后拒绝新地址直至宿主重启，不淘汰仍用于防止重复动作的记录。

参考 AndPods4.3.8 本地研究中的连接音量功能：
`service/BackgroundService.java:534–564,1222–1230`、`util/VolumeUtil.java:61–65,96–97`、
`activity/AutoAudioSettingActivity.java:479`。未复制其代码或资源；本实现使用精确路由和
已有认证状态驱动，不复制固定延迟、后台服务或断开恢复行为。低电量语音播报属于后续
独立切片，本项不启用 TTS。

验证覆盖默认关闭／设置往返、一次性作用域、回放、晚到准入、10秒截止、用户改音量、
通话／对话／控制权取消、producer死亡、旧连接、异常清理，以及真实 AudioManager／
AudioDeviceInfo 的路由、音量写入和回调移除。最终构建和具体耳机的实际音量体验应分别记录。
