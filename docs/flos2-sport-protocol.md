# Dreame / TheAstro FloS2 运动耳机协议适配

HyperEars 实现流宇系运动耳机（Dreame Flo S2 与 TheAstro OpenPro S2，同一硬件双品牌）接入
MiLink 所需的最小子集：整机电量读取与音效切换。运动记录、结果文件同步、MP3 模式、语音
播报、OTA 与其他厂商 App 功能不属于本适配范围。

## 1. 候选选择

当前登记的具体型号为 TheAstro OpenPro S2（实机验证）；Dreame Flo S2 为同硬件双品牌，处于
家族外推。两个品牌的设备以不同广播名出现，但协议内设备名相同，均为 `Flo S2`。具体型号
Adapter 接受以下规范化名称：

- `openpros2`。

名称包含 `flos2`、`openpros2` 或 `haptifit` 的标准蓝牙耳机进入同协议家族探测；广播携带
私有服务 UUID `AC00` 的设备同样进入候选。名称与 UUID 只用于选择候选 Adapter，不会直接
开放私有电量或音效控制。HyperOS 已原生接管的耳机仍由平台保留，不会进入 FloS2 匹配链。

## 2. GATT 端点

私有协议使用以下服务和特征：

| 用途 | UUID |
|---|---|
| 主服务 | `0000AC00-0000-1000-8000-00805F9B34FB` |
| 命令写入 | `0000AC01-0000-1000-8000-00805F9B34FB` |
| 状态通知 | `0000AC02-0000-1000-8000-00805F9B34FB` |

端点在当前 A2DP/HFP 音频设备上直接打开；写入使用无响应模式（与厂商 App 行为一致）。
设备不暴露标准电池服务（0x180F），电量只能来自私有协议。

## 3. 帧格式

通知和命令共用同一帧结构：

```text
AE | primary | sub | payloadLength | payload[payloadLength] | CRC16 LE
```

- `AE`：帧起始标记；
- `primary`：主类型，`66` 状态/配置/事件、`67` 运动/音频控制、`68` 文件传输（本适配不使用）；
- `sub`：子命令；应答子命令为请求子命令 `or 0x80`；
- `payloadLength`：单字节载荷长度，可为 `00`；
- CRC：CRC-16/CCITT-FALSE（poly `0x1021`，init `0xFFFF`，无反转），覆盖标记至载荷末字节，
  小端传输。

流式解码器按长度与 CRC 双重校验分片与粘包；CRC 不合的帧被丢弃，不产生协议事件，也不能
确认能力。

## 4. 全量状态

连接后发送状态查询：

```text
查询：AE 66 FF 00 D8 E6
响应：AE 66 FF 48 <72 字节定长载荷> <CRC>
```

72 字节载荷中与本适配相关的字段（偏移为载荷内 0 基，均经实机采集核对）：

| 偏移 | 字段 | 说明 |
|---|---|---|
| 0–1 | RTC 秒计数 | u16 LE，滚动值 |
| 6–10 | 固件版本 | ASCII，如 `1.6.6` |
| 11–15 | 硬件版本 | ASCII |
| 16–20 | MCU 固件版本 | ASCII |
| 25–26 | 电量 | u16 LE，0–100 |
| 27–30 | 存储 | 已用/总量，u16 LE |
| 36–41 | 设备名 | ASCII 定长，`Flo S2` |
| 42–47 | MAC | 反序 |
| 48 | 泳池长度 | 单字节 |
| 49 | 音效档位 | 单字节，见第 6 节 |
| 55–70 | 序列号 | ASCII 定长 |

未列出的字段尚未证实语义，解析器不读取。

## 5. 电量

电量有两个来源，数值一致：

```text
状态内嵌：72 字节载荷偏移 25–26（u16 LE）
主动推送：AE 66 E0 02 <电量 u16 LE> <CRC>，约 20–30 秒周期
```

实测要点：

- 电量按 **10% 一档量化**（105 个 CRC 校验样本值域 {60,70,80,90}，无一个非 10 倍数），
  线上不存在 71、75 这类个位数值；协议只承载设备量化后的档位值。
- 协议只有单一电量字段，没有左右耳与充电盒分量；HyperEars 将其投影为整机电量。
- 充电状态不可观测：耳机插入充电线即关机断连，推送中的充电位恒为 0。
- 收到合法电量帧后，电量来源从系统整机升级为私有协议；此前始终使用 Android 系统整机电量
  回退。

## 6. 音效切换

音效命令位于运动控制族（厂商 App 内部符号 `setEqMode`）：

```text
设置：AE 67 03 01 MM <CRC>
应答：AE 67 83 01 00 <CRC>
```

| `MM` | 语义 |
|---|---|
| `00` | 标准 |
| `01` | 游泳 |
| `02` | 人声 |
| `03` | 增强 |

应答只表示执行结果，不回显档位；耳机对 App 发起的音效切换也不推送任何事件帧。因此每次
设置后通过统一回读流程重新查询全量状态，只在收到合法设备状态时更新卡片状态。

音效不是 MiLink 原生噪声三态的一部分，以 `flos2.sound_effect` 专属状态承载，仅在状态帧
确认后开放。卡片呈现复用 MiLink 原生模式卡槽位（与 FitClip Ultra 游戏模式同款机制）：
标题替换为"音效"，三个原生项临时替换为四个同原生类项（标准/游泳/人声/增强），解绑时
恢复原项。

## 7. 能力与失败回退

`FloS2ProtocolSession` 初始只发送全量状态查询，两类能力独立确认：

- 合法状态响应或电量推送把电量来源升级为私有协议；
- 状态响应中的音效字段开放 `flos2.set_sound_effect` 控制与 `flos2.sound_effect` 状态；
- 任一合法状态帧可以确认当前传输承载 FloS2 协议；
- 状态查询始终无合法响应时，直接切换到标准耳机 Adapter。

标准回退仍提供 MiLink 流转、系统音量和 Android 系统整机电量，不建立 FloS2 私有通道。

## 8. 代码边界

- `FloS2WireCodec`：纯字节帧、流式解码、状态/电量解析与音效命令编码；
- `FloS2ProtocolSession`：初始查询、能力证据、控制回读和状态事件；
- `FloS2EarbudAdapter` 层级：双品牌型号/家族匹配、端点候选与失败回退；
- Android 运行层：执行 Adapter 声明的有界端点解析，不包含 FloS2 名称或协议字段。

## 9. 来源与证据

- 证据等级：**实机验证**。协议结论来自对官方伴侣 App（Android 平台）蓝牙链路的独立逆向
  分析，以及 2026-10 的两场实机 HCI 采集（含 9 次音效切换逐帧核对、105 个电量样本统计，
  全部帧经 CRC 校验）。
- 本文档如实区分：协议本身已完成实机验证；HyperEars 适配器的最终实机复核（MiLink 卡片
  实际显示与控制）按项目维护流程单独进行，合入不代表补齐该复核。
- HyperEars 在自身 Adapter、ProtocolSession 与 WireCodec 边界内实现所需的互操作协议，
  不分发厂商 App、界面、图片、资源或构建产物。
