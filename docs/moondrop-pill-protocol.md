# MOONDROP PILL 协议适配

HyperEars 为水月雨 PILL 耳夹款蓝牙耳机（蓝牙名称 `MOONDROP PILL`）实现 MOONDROP GAIA
线协议族的最小互操作子集：API 版本握手与左右耳电量读取。协议确认前电量沿用 Android
系统整机，确认后切换为私有左右耳电量。

该型号为**无降噪的 OWS 耳夹耳机**：官方 App 设备页只有增益档位、场景预设与在线交互 DSP，
没有任何噪声控制入口；完整实机抓包中也没有任何噪声命令。因此 HyperEars 不实现、不发送、
不开放任何噪声模式。

PILL 是 ZZZ-ANGELS-OWS（水月雨 × 绝区零「妄想天使·闪亮登场」耳夹款）的基础款，两者共用
同一 GAIA 协议子集。本适配复用已实机复核的 `MoondropZzzAngelsWireCodec` 与
`MoondropZzzAngelsBatteryPolicy`，**不改动 ZZZ-ANGELS-OWS 的 Adapter 与会话实现**。

## 1. 判型

Adapter 只接受规范化完整名称 `moondroppill`（实机蓝牙名称 `MOONDROP PILL`，规范化规则为
小写后仅保留字母与数字）。

实机未观察到独立的 `-LEA` 广播名称，因此本适配不声明 LEA 排除规则；这与
ZZZ-ANGELS-OWS 不同，后者实测广播不可用的 `ZZZ-ANGELS-OWS-LEA` 身份。若后续固件出现
独立 LE Audio 身份，应补充证据后再收窄名称范围。

更宽的别名（例如仅 `PILL`）未获实机证据，不予认领，避免误匹配其他产品。

## 2. 传输

使用 Bluetooth SIG 标准 SPP UUID `00001101-0000-1000-8000-00805f9b34fb` 建立 RFCOMM
通道。设备 SDP 实机确认该 UUID，另登记 A2DP `110b`、AVRCP `110e`、HFP `111e`；官方 App
的协议会话实测运行在该 RFCOMM 通道的 **DLCI 2** 上。该 UUID 只负责建立端点，不参与品牌
或型号判定。

设备类为 `0x240404`（Audio/Video，Wearable Headset），蓝牙身份为 DUAL。同一链路的手柄上
另有 HFP AT 命令通道（DLCI 4）与 AVRCP 通道（DLCI 13），两者承载 Android 标准耳机能力，
与私有协议无关。

## 3. 帧格式

与 MOONDROP Robin / Pudding / ZZZ-ANGELS-OWS 完全相同的布局（实测字节）：

```text
FF TT 00 LL HH CC SS OO [parameters...]
```

- `TT`：`01` 为 API 版本请求，`04` 为设备响应；
- `LL HH`：参数长度，小端序，只覆盖 parameters；
- `CC SS OO`：厂商字节与命令字（电量 `1D 1A 01`，握手 `0A 03 00`）；
- 长度字段之外的字节一律忽略：实测部分帧在载荷后带一个尾字节（如 `FF`）。

解码器按长度字段处理 RFCOMM 分片与粘包，拒绝非法类型、超长帧和字段不完整的响应。

## 4. 握手

```text
发送：FF 01 00 00 00 0A 03 00
响应：FF 04 00 04 00 0A 83 00 00 04 03 01
```

响应参数共 4 字节：`00` 为成功状态，其后为版本三元组（实测 `04 03 01` = 协议 v4、
API 3.1），与 ZZZ-ANGELS-OWS 固件 1.2.0 的回答逐字节相同。只有合法握手响应到达时私有
协议才进入确认状态；校验要求状态字节为 `00` 且协议版本在官方版本表（1..4）内，版本三元组
其余字节不固定（固件可变，宽松校验避免误拒）。

三次独立连接的握手回答一致。状态字节非零视为明确不兼容，设备会话按统一的有界退避与
休眠唤醒路径处理，不会改判为其他厂商。

## 5. 电量

实测完整交换（固件 1.6.0）：

```text
发送：FF 04 00 00 00 1D 1A 00              支持组件查询
响应：FF 04 00 02 00 1D 1B 00 01 02        支持组件 = 左(01)、右(02)，无充电盒
发送：FF 04 00 02 00 1D 1A 01 01 02        电量查询（左、右）
响应：FF 04 00 04 00 1D 1B 01 01 64 02 50  左 100%、右 80%
```

`01 64` = 100%、`02 50` = 80%，与官方 App 设备页同时显示的 L 100% / R 80% 精确对应，
构成交叉验证。

已确认的查询响应（`1D 1B 01`）使用 `<id> <值>` 对：

```text
01 <左耳> 02 <右耳> [03 <充电盒>]
```

- 组件 id 来自官方实现的电量组件表：`01` 左耳、`02` 右耳、`03` 充电盒；
- 左/右耳 `1..100` 为有效值，`00` 与 `FF` 解码为未知；
- 充电盒 `0..100` 为有效值（空盒 `0` 是真实状态），`FF` 解码为未知；
- 1 至 3 对、任意顺序均可解析；重复或未知 id、奇数长度、非法百分比拒绝整帧；
- 本帧未包含的组件保留原值；明确报告 `00`／`FF` 的未知组件清除旧值。

**本型号实测只支持左、右耳两个组件**（支持组件响应 `01 02`），两对响应是预期形态。
解析保留 `03` 盒组件的兼容以覆盖家族差异，设备回传才显示，未回传的组件保持未知，
不构造充电状态。

支持组件响应 `1D 1B 00` 的操作码为 `00`，不是电量读数，解析器按未知帧忽略，不开放私有
电量。固件版本响应同理（见第 7 节）。

协议确认前电量沿用 Android 系统整机；收到合法电量帧后切换为私有电量并发布。连接初期
的分侧回报在会话内合并（缺失组件保留上一次已知值），并通过 `500/800/1200/1600 ms`
有界序列补齐；补齐成功或达到重试边界后才提交首次私有电量。该策略复用
`MoondropZzzAngelsBatteryPolicy`，不改动 Pudding／Robin／MIRAGE／ZZZ-ANGELS-OWS 的既有策略。

本轮抓包只观察到 `1D 1B 01` 查询响应，未观察到 `1D 1A 81` 或 `1D 81 01` 主动推送变体，
因此与 ZZZ-ANGELS-OWS 一致，暂不接受推送变体，待提供实际主动帧后再加入。打开卡片和
主页的标准 `Refresh` 仍会查询当前电量。

## 6. 噪声控制：不适用

该型号无降噪硬件与功能。官方 App 的设备页与功能设置中没有任何降噪、通透或模式入口
（实机 UI 核对），151 帧抓包中 `1D 40`／`1D 41` 噪声命令为**零条**。因此模块不发送任何
噪声查询或写入；即使收到家族噪声帧也按未知帧忽略，不开放任何噪声控制，MiLink 卡片不显示
模式控件。

## 7. 未开放的设备功能

官方 App 为该型号提供低/中/高增益三档、场景预设与在线交互 DSP（实机 UI 确认）。抓包中
出现的其他厂商 29 命令包括：

| 命令 | 实测回答 | 说明 |
|---|---|---|
| `1D 00 01` → `1D 01 01` | 19 字节特性枚举 | BASIC 支持特性列表 |
| `1D 00 07 <id>` → `1D 01 07` | 空参数 | 逐特性查询，本轮回答均为空 |
| `1D 00 05` → `1D 01 05` | `31 2E 36 2E 30` | 固件版本 ASCII `1.6.0` |
| `1D 00 0D` / `1D 01 0D` | — | 特性配置 |
| `1D 00 0C` / `1D 01 0C` | — | 特性配置 |
| `1D 0A 05` → `1D 0B 05` | 39 字节 | 音频/DSP 相关数据块 |
| `1D 1C 01` → `1D 1D 01` | `01 32 00` | 未确认语义 |
| `1D 1E 01` → `1D 1F 01` | `00` | 未确认语义 |
| `1D 28 01/03/05/06` → `1D 29 …` | 含已配对设备名 | 双设备连接（ONEBRINGTWO）相关 |

这些能力需要额外的类型化状态、控制请求与卡片证据，且详细配置按项目范围交给厂商 App，
HyperEars 当前不开放，本文只记录其存在。`1D 29 05/06` 的回答含用户设备名称等个人标识，
不入库、不在本文展开。

## 8. 代码边界

- `MoondropZzzAngelsWireCodec`（复用，未改动）：纯字节帧、流式解码、握手与电量字段校验；
- `MoondropZzzAngelsBatteryPolicy`（复用，未改动）：连接初期有界补齐与显式未知清理；
- `MoondropPillAdapter`：名称判型、SPP 传输、电量证据门控、控制 App 声明；
- `MoondropPillProtocolSession`：握手进度、电量查询与分侧合并；
- `EarbudAdapterRegistry`：在 `moondropGroup` 内注册于家族回退 `MoondropEarbudAdapter` 之前；
- MiLink：只读取标准电量投影，不增加自定义卡片或 View Hook。

控制 App 沿用 `ControlAppCatalog.moondrop`
（`com.moondroplab.moondrop.moondrop_app`），该条目已由 ZZZ-ANGELS-OWS 登记并实机验证
运行时退避，本次不新增包名、不改 `scope.list`。包名只定义导航目标与控制权边界，
不参与耳机判型。

与 MOONDROP Robin、Pudding 同族的帧格式与命令方言见
[`moondrop-robin-protocol.md`](moondrop-robin-protocol.md) 与
[`moondrop-pudding-protocol.md`](moondrop-pudding-protocol.md)；直接同构的衍生款见
[`moondrop-zzz-angels-protocol.md`](moondrop-zzz-angels-protocol.md)。HyperEars 根据可
互操作的协议事实独立实现，不分发厂商 App、固件、图片或反编译产物。

## 9. 验证状态

以下项目已在实机（Xiaomi 13 / HyperOS 4.0，模块 3.2.1 debug，固件 1.6.0）复核：

- 首次连接与私有左右耳电量投影，电量来源为私有协议；
- MiLink 卡片显示左右耳分别读数，充电盒显示为不支持；
- 重连：协议栈重启后重新握手，`FF 01 00 00 00 0A 03 00` →
  `FF 04 00 04 00 0A 83 00 00 04 03 01` 与抓包一致；
- 厂商 App 运行时让位，退出后经退避重试恢复；
- “更多设置”跳转至厂商 App。

已知限制：

- 单耳入盒期间该耳读数冻结：跨数分钟的四次 `Refresh` 均返回同一帧 `1D 1B 01 01 64 02 5A`，
  出盒后第一次普通 `Refresh` 即变为 `1D 1B 01 01 64 02 64`，未重新握手；`charging` 恒为
  `false`，官方 App 显示同一读数，与 ZZZ-ANGELS-OWS 固件 1.2.0 的限制同源。模块保留设备
  实际回报，不按数值长期不变猜测离线或充电；
- 该型号只回传左右耳两个分量，充电盒状态不构造。
