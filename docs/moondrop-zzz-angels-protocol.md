# MOONDROP ZZZ-ANGELS-OWS 协议适配

HyperEars 为水月雨 × 绝区零「妄想天使·闪亮登场」耳夹款蓝牙耳机（`ZZZ-ANGELS-OWS`）
实现 MOONDROP GAIA 线协议族的最小互操作子集：API 版本握手与左右耳电量读取。协议
确认前电量沿用 Android 系统整机，确认后切换为私有左右耳电量。

该型号为**无降噪的 OWS 耳夹耳机**：官方 App 无任何噪声控制入口，完整实机抓包中也
没有任何噪声命令，因此 HyperEars 不实现、不发送、不开放任何噪声模式。

## 1. 判型

Adapter 只在下列名称规则之一成立时选择 ZZZ-ANGELS-OWS：

- 规范化完整名称为 `zzzangelsows` 或 `moondropzzzangelsows`；
- 规范化名称同时包含 `zzz` 与 `angel`。

以上规则排除 `-LEA` 后缀：该耳机同时广播 `ZZZ-ANGELS-OWS-LEA` 这一独立的 LE Audio
身份，官方 App 也无法连接它（故意不可用），不得被本 Adapter 认领。蓝牙名称
`ZZZ-ANGELS-OWS` 为实机确认。

## 2. 传输

使用 Bluetooth SIG 标准 SPP UUID `00001101-0000-1000-8000-00805f9b34fb` 建立 RFCOMM
通道。设备 SDP 记录实机确认该 UUID（另有 A2DP `110b`、AVRCP `110e`、HFP `111e`），
官方 App 的协议会话也实测运行在该 RFCOMM 通道。该 UUID 只负责建立端点，不参与品牌
或型号判定。

官方 App 的 GAIA 客户端还支持 GAIA 专用 RFCOMM UUID `00001107-D102-11E1-9B23-00025B00A5A5`
与 BLE GATT 服务 `00001100-D102-…`，但本设备 SDP 未登记、抓包也未使用这些端点，
因此不声明为候选传输。

## 3. 帧格式

与 MOONDROP Robin / Pudding 完全相同的布局（实测字节）：

```text
FF TT 00 LL HH CC SS OO [parameters...]
```

- `TT`：`01` 为 API 版本请求，`04` 为设备响应；
- `LL HH`：参数长度，小端序，只覆盖 parameters；
- `CC SS OO`：厂商字节与命令字（电量 `1D 1A 01`，握手 `0A 03 00`）；
- 长度字段之外的字节一律忽略：实测响应在载荷后常带一个尾字节（如 `40`）。

解码器按长度字段处理 RFCOMM 分片与粘包，拒绝非法类型、超长帧和字段不完整的响应。

## 4. 握手

```text
发送：FF 01 00 00 00 0A 03 00
响应：FF 04 00 04 00 0A 83 00 00 04 03 01 40
```

响应参数共 4 字节：`00` 为成功状态，其后为版本三元组（实测 `04 03 01` = 协议 v4、
API 3.1，尾字节 `40` 不参与校验）。只有合法握手响应到达时私有协议才进入确认状态；
校验要求状态字节为 `00` 且协议版本在官方版本表（1..4）内，版本三元组其余字节不固定
（固件可变，宽松校验避免误拒）。状态字节非零视为明确不兼容，设备会话按统一的有界
退避与休眠唤醒路径处理，不会改判为其他厂商。

## 5. 电量

实测完整交换（固件 1.2.0）：

```text
发送：FF 04 00 00 00 1D 1A 00              支持组件查询
响应：FF 04 00 02 00 1D 1B 00 01 02        支持组件 = 左(01)、右(02)，无充电盒
发送：FF 04 00 02 00 1D 1A 01 01 02        电量查询（左、右）
响应：FF 04 00 04 00 1D 1B 01 01 3C 02 64  左 60%、右 100%
```

查询响应（`1D 1B 01`）与主动推送（`1D 1A 81`）使用 `<id> <值>` 对：

```text
01 <左耳> 02 <右耳> [03 <充电盒>]
```

- 组件 id 来自官方实现的电量组件表：`01` 左耳、`02` 右耳、`03` 充电盒；
- 左/右耳 `1..100` 为有效值，`00` 与 `FF` 表示未连接或不可读并解码为未知；
- 充电盒 `0..100` 为有效值（空盒 `0` 是真实状态），`FF` 解码为未知；
- 2 或 3 对、任意顺序均可解析；重复或未知 id、奇数长度、全部不可读的帧被拒绝。

**本型号实测只支持左、右耳两个组件**（支持组件响应 `01 02`），两对响应是预期形态；
解析保留 `03` 盒组件的兼容以覆盖家族差异（Pudding 会回传盒电量），设备回传才显示，
未回传的组件保持未知，不构造充电状态。

协议确认前电量沿用 Android 系统整机；收到合法电量帧后切换为私有电量并发布。连接
初期的分侧回报在会话内合并（缺失组件保留上一次已知值），并通过 `500/800/1200/1600 ms`
有界序列补齐；补齐成功或达到重试边界后才提交首次私有电量。

## 6. 噪声控制：不适用

该型号无降噪硬件与功能。官方 App 的设备页和功能设置中没有任何降噪、通透或模式
入口（实机确认），抓包中 AudioCuration（feature 8）与 ANC_V2（feature 32）命令为
零条。因此模块不发送任何噪声查询或写入；即使收到家族噪声帧也按未知帧忽略，不开放
任何噪声控制，MiLink 卡片不显示模式控件。

## 7. 未开放的设备功能

官方 App 为该型号提供低/中/高增益三档、提示音开关与音量、续航优先模式、语音包
（爱芮/南宫羽/千夏）、场景预设、STI 个人声音偏好、在线交互 DSP、LHDC/LC3 Codec
设置与双设备连接。抓包中对应命令集中在厂商 29 的 BASIC（feature 0，含支持特性
枚举）、DAC_GAIN（15）、DYBASS（27）、CODEC_TYPE（16）、VOICE（14）与
ONEBRINGTWO（20）等 feature。这些能力需要额外的类型化状态、控制请求与卡片证据，
HyperEars 当前不开放，本文只记录其存在。

## 8. 代码边界

- `MoondropZzzAngelsWireCodec`：纯字节帧、流式解码、握手与电量字段校验；
- `MoondropZzzAngelsProtocolSession`：握手进度、电量查询与分侧合并；
- `MoondropZzzAngelsAdapter`：名称判型（排除 LEA）、SPP 传输、电量证据门控与连接
  初期的有界补齐；
- MiLink：只读取标准电量投影，不增加自定义卡片或 View Hook。

与 MOONDROP Robin、Pudding 同族的帧格式与命令方言见
[`moondrop-robin-protocol.md`](moondrop-robin-protocol.md) 与
[`moondrop-pudding-protocol.md`](moondrop-pudding-protocol.md)。HyperEars 根据可互操作的
协议事实独立实现，不分发厂商 App、固件、图片或反编译产物。
