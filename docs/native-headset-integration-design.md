# HyperOS 原生耳机提示接入设计

状态：实现纳入 3.0.0；已完成本机 HyperOS 4 的主要展示验证，其他宿主与官方设备共存继续回归。
更新日期：2026-10-26。

以 `main` 的 `361d27970002ea86a778a7eaf722c3c022975591`（v2.8.0）为代码基线。
功能在 `codex/native-headset-presentation` 开发后合入主线。本文保留研究证据、职责和验收条件，
第 2 节的独立实验与第 9 节的完整包验证分别记录，不能用早期合成状态实验代替所有设备实测。
设计遵循 [贡献规则](../CONTRIBUTING.md#设计规则) 和
[模块架构](system-module-architecture.md)。

## 1. 目标与范围

沿用现有 Adapter 的识别、协议会话和状态，把符合条件的设备接入 HyperOS 已有的耳机展示流程。
系统负责界面、动画和窗口生命周期；模块负责提供真实状态、限定展示归属，以及将真实断开等
生命周期事件送到原生关闭回调。自动提示还须服从宿主的显示条件和流转去重。

| 项目 | 本轮目标 | 边界 |
| --- | --- | --- |
| 连接后的耳机提示／超级岛 | 将真实连接和当前电量提供给原生耳机通知服务 | 由宿主决定最终展示形式；不自行组装超级岛界面 |
| 连接后的电量弹窗 | 复用已验证的 AirPods Controller 展示边界，使用 Adapter 的电量 | 只为本模块窗口提供状态；不把连接伪装成开盖 |
| 耳机详情通知 | 提供可关闭的原生电量通知，打通点击、断开和清理 | 与短暂的连接提示分别管理 |
| 流转提示与结果 | 保留现有 MiLink 路径，验证与新增提示的去重 | 不再次发布同一流转的连接／失败提示 |
| 未配对时的开盖发现、配对弹窗 | 不在本轮范围 | 需要真实开盖／广播协议，当前统一模型没有这些事件 |
| 状态栏蓝牙电量图标 | 不在本轮范围 | 不增加 SystemUI 电量图标 Hook |

“连接后的电量弹窗”不承诺耳机尚未连接时显示，也不承诺仅开盖但没有新连接时再次显示。
新增接口必须支持系统整机电量回退；私有协议失败不影响已有标准音频、音量和流转。

### 2.4 路线选择和接入限制

1. `BluetoothHeadsetService.checkIsMiTWS` 的内部路径会读取设备缓存的型号 ID 和通知资源资格。
   写入一个小米耳机型号 ID 会改变系统判型，影响 HyperEars 的原生归属保护。
2. `MiuiBluetoothNotification.updateParameters` 还会读取宿主缓存的电量和佩戴状态。
   单独修改一次显示参数，不能保证异步执行时仍使用同一份数据。
3. `FragmentHandler.handleThirdPartyBattery` 可以接受三路电量，但它还会保存缓存、通知其他监听者，
   后续涉及查找、LE Audio 等路径。它是待核实副作用的候选入口，不能视为纯 UI 更新函数。
4. 原生 `+XIAOMI` 第三方入口解析特定 AT/TLV 数据，并更新身份及功能信息。
   它不等于任意应用均可调用的通用注册 API。本方案不生成虚构 AT 包来驱动它。
5. 详情通知的单设备取消也检查 `checkSupport`。强制创建成功不代表能够取消；
   它的详情动作还会进入小米专用耳机设置页，必须核实第三方设备的正确去向。
6. FastConnect 部分类位于动态插件中。需要先确认插件已加载及实际 ClassLoader，
   不能在包加载阶段找不到类后不断重试。
7. 普通小米 Controller 的 `parseIntentAdvData` 会调用 `unpairForLEA`，特定广播和系统条件还会
   修改 LE Audio 状态、执行取消配对。不能靠构造一份假广播把该发现／配对入口变成纯电量入口。
8. AirPods Controller 的原服务注册会占用 Helper 的共享回调，并触发 500 ms BLE 扫描。
   原始 Helper 还使用全局协议选择值 16。正式方案仅复用窗口，隔离这部分品牌服务。

本轮选择 **AirPods 原生窗口 + 窗口专属的只读状态接口** 作为电量弹窗方案。
Sony Controller 的早期实验只证明原生 UI 可被外部状态驱动，按维护者要求不作为正式接入基础。
普通小米的连接提示服务仍可作为独立后端；排除的是依赖虚构广播的发现／配对入口。

及流转记录内部方法已混淆。`NativeHostResolver` 优先验证具名契约，缺失时在单次后台扫描中

- 流转记录类型来自原生 `addConnectManagerList` 的确切参数；连接消息处理器中唯一调用的

- 通知点击核对 `BroadcastReceiver.onReceive`、详情通知 action 和设置跳转 action。
- 原生弹窗插件继续使用原有稳定 Controller / callback 契约，展示资源与数据源隔离规则不变。

## 3. 职责划分

保持 `Adapter → ProtocolSession → WireCodec` 的现有分层。新增代码集中在 `system-module`，
成为现有状态的另一个消费者，不为每个品牌添加一套系统提示实现。

| 位置 | 职责 | 不承担的工作 |
| --- | --- | --- |
| 现有 `EarbudAdapter` | 候选身份、已确认能力、协议策略、状态接受／暂缓 | 系统 Activity、通知资源或弹窗时间控制 |
| 现有 `ProtocolSession` / `WireCodec` | 协议对话与纯字节解析 | 系统 UI 和原生通知调用 |
| 现有 Bluetooth 会话管理 | 管理设备会话，发布已接受状态，记录真实连接来源 | 按品牌决定哪种弹窗或图片 |
| 系统耳机宿主登记与 MiLink 原始接管报告 | 保护系统已支持设备；展示检查独立于 MiLink | 依据模块 Hook 后的结果反推系统归属 |
| `NativeHeadsetProjection` | 把现有状态投影为展示需要的名称、形态和电量 | 解析协议、补造数值、修改 Adapter 能力 |
| `NativePresentationRuntime` / `NativeOwnershipStore` | 校验归属与生命周期，去重，维护本模块创建的展示记录 | 蓝牙连接、协议重试或型号稳定状态机 |
| `NativeConnectionHint` / `AirPodsWindowBridge` / `NativeDetailNotification` | 封装经验证的宿主入口、参数和资源差异 | 公共 Adapter 中的 HyperOS 分支 |
| 后端内部的窗口绑定 | 关联一次授权、Controller、ServiceConnection、状态版本及本地回调 | 改写原生 Apple 数据库或建立另一套协议会话 |
| `XiaomiBluetoothProcessHook` | 宿主生命周期、动态插件就绪和必要的限定语义 Hook | 系统范围的 View、Socket、反射扫描 Hook |

这些组件按职责组合，实际出现版本差异时再拆分后端，不按每个 OS 版本预设子类。

状态沿以下链条传播：

```text
协议响应 → ProtocolSession 事件 ─┐
Android 电量 → Adapter 回退入口 ─┴→ Adapter 接受状态
    （HOLD 的状态留在原有策略内）
    → EarbudDeviceSession / EarbudConnectionManager
    → 已接受的 EarbudState + 受信任的归属、连接元信息
    → NativeHeadsetProjection
    → NativeHeadsetCoordinator
    → HyperOsHeadsetBridge
    → 原生耳机服务 / Controller
    → 系统负责显示和消失
```

MiLink 卡片、应用主页和原生提示消费同一份已发布状态。后端内可保留展示投影及提交版本，
不能建立会自行改写左右耳电量或噪声模式的第二份设备状态。

## 4. 归属、状态和连接事件

### 4.1 原生接管检查独立于 MiLink

从 3.1.1 起，展示准入由 `com.xiaomi.bluetooth` 宿主直接确认。蓝牙进程发布当前设备会话，
原生展示后端读取同一宿主管理的登记记录，并向蓝牙进程回传绑定 `sessionToken` 的结果。
蓝牙进程校验发送者、会话与生命周期后，统一更新元数据并发布快照。MiLink 是否启动、是否
创建控制器、是否打开卡片，都不再是弹窗、超级岛和电量通知的前提。

宿主登记的依据已与原生 `isMiTWS/checkIsMiTWS`、`checkIsAirPods`、
`checkIsThirdPartyHeadset` 实现核对：

| 宿主记录 | 含义 |
| --- | --- |
| `FragmentHandler.HEADSET_DEVICE_INFO` 指向的 `DeviceIdCached`，键 `saved<address>` | 原生登记的设备 ID |
| `HEADSET_DEVICE_ID_INFO`，键 `saved<address>` | 原生设备 ID 的回退存储 |
| `AirpodsModel`，键 `<address>-type` | 原生 Apple 设备登记 |
| `DeviceIdCached`，键 `third_party_type<address>` | 原生第三方耳机登记 |

这些数据由系统维护。模块只在该宿主进程读取，不创建、修改或删除登记，也不把用于 MiLink
卡片承载的模块设备 ID 写入其中。原生 Binder 的部分查询会先限制调用方；直接把其权限
拒绝返回的 `false` 当作“不支持”会误判，因此展示检查读取其底层登记，而不绕过权限检查。

解析前优先校验宿主的具名 Binder 查询方法、返回类型及 `HEADSET_DEVICE_INFO` 常量；具名入口
缺失时，使用第 2.5 节的唯一 DEX 登记读取契约。不兼容或读取异常保持 `UNKNOWN`。
任一原生登记非空即为 `SYSTEM`，包括已登记但不属于 MiLink
较窄支持列表的设备；只有四项均为空才确认 `HYPEREARS`。该检查不使用品牌、名称或 UUID
重新判型，目标始终是蓝牙进程已发布的有效候选。

| 归属 | 展示行为 |
| --- | --- |
| `UNKNOWN` | 等待有效的宿主登记读取；不创建展示 |
| `HYPEREARS` | 当前会话、用户设置与宿主能力均有效时允许提交 |
| `SYSTEM` | 官方路径优先；停止模块会话及其展示 |

每个会话只缓存有效读取结果，`UNKNOWN` 不缓存。当前地址的原生登记键变化或用户手动预览时
重新读取；宿主契约准备完成后重新处理已有会话。不轮询，不绑定额外服务，也不创建蓝牙通道。
登记变化通过 SharedPreferences 监听传入宿主主线程；迟到的
结果须通过当前会话 token 校验。已确认系统接管的地址保持粘性，旧的模块确认不能覆盖它。

MiLink 仍观察自身 `checkIsMiTWS` 的原始结果并保留系统接管上报；它也接收蓝牙进程发布的
`SYSTEM` 结果，停止该地址的模块卡片适配。MiLink 不再发送正向展示许可，原有主动检查和
临时查询绑定已移除。

2026-10-28 的琉璃 X、2026-10-30 的琉璃 Ultra 日志均暴露了原展示对 MiLink 启动时序的
依赖。新实现的本地回归覆盖无需 MiLink 的准入、各类原生登记保护、登记后到与提示去重；
这些测试不能代替各 ROM 的实机显示验证。

手动预览仍保留原生设备保护，并使用蓝牙进程已发布的统一元数据；刚取得本地许可、尚未收到
统一快照时返回“状态正在同步”，不自行改写快照的归属或版本。预览跳过自动连接的时效和
历史展示去重，但保留连接处理中、当前窗口占用、有效电量和用户可见性检查。
预览结果通过带请求 ID 和发送者校验的广播返回应用。3 秒超时只提示宿主未响应，
不重发请求、不重试显示；离开调试页时取消等待并注销接收器。

### 4.2 复用统一状态模型

读取 `EarbudState.adapter`、`EarbudState.lifecycle` 和 `DeviceFeatureSnapshot`，
从已有 `BatteryFeatureState` 获取电量。后端按已确认能力和电量来源投影：

| 输入 | 输出规则 |
| --- | --- |
| 只有 Android 整机电量 | 使用原生整机电量形式；不能复制成左右耳两个百分比 |
| 私有协议只报告整机电量 | 同样按整机处理，不能由 `PRIVATE_PROTOCOL` 推定存在独立左右耳数据 |
| 已确认的左右耳／盒电量 | 分别映射到相应组件；未知组件仍为未知 |
| 合法的 0% | 保留其既有协议语义；展示层不再全局修改 0 的含义 |
| Adapter 暂缓接受的报告 | 不进入系统提示，不绕过 `FeatureReportDecision.HOLD` |
| 厂商 App 退避 | 使用会话当前发布的标准回退投影；不继续展示旧私有电量 |
| 没有佩戴、开盖状态 | 不伪造已佩戴、已开盖、已入盒或正在充电 |
| 宿主无法表达某项数据 | 省略该项或停用不合适的展示形式，保留已有 MiLink 能力 |

现有 `EarbudBattery.fromAggregate` 为 MiLink 把单个值复制到左右耳，同时保留 `overall`。
新投影须结合 `batterySource`、`overall` 和 Adapter 形态区分整机与组件数据，
不能只见左右耳字段有值就输出两只耳机。私有协议的 `TWS_AGGREGATE` 也遵守该规则。
当前单电量布局通过 `wearType=3` 选择，并使用宿主模型的左电量槽作为显示值；
这是后端的模板参数，不改变 `EarbudBattery` 的领域语义。
TWS 只有整机数据时，同样使用单值布局；在本次同步提示调用内，将原生
`getResourceUri("single_battery_head", null)` 的资源请求定向为已有的 `earphone` 资源，
显示耳机形态与一个百分比。其余设备和调用不变；入口不兼容时只停用该单值 TWS 提示，
保留弹窗、通知及 MiLink 电量。此资源映射已依据原生参数构建代码核对，待实机复核视觉效果。

原生参数中的未知值、佩戴“不支持”值和充电位由版本后端转换，并用该版本证据验证。
不得把 `null` 转成 0%，也不得借用其他型号的全部能力来获得图片或布局。
本轮不向超级岛增加降噪按钮；以后确有原生控制入口时，仍走既有 `ControlRequest`。

### 4.3 真实连接与模块会话分开

`EarbudState.connected` 表示当前集成是否可用，会受到私有握手和通道状态影响，不能用作
物理蓝牙连接边沿。现有
[EarbudConnectionManager](../system-module/src/main/java/dev/hyperears/runtime/EarbudConnectionManager.kt)
重选适配器时会结束并重建会话；暂停也会发布会话结束。
这些路径可能产生 `systemProfile = DISCONNECTED` 的最终快照，而物理蓝牙仍连接。
因此 `sessionToken` 变化和快照中的断开不能独立用作连接提示触发条件。

在现有 Android Profile 事件入口记录真实连接代号和来源，随状态传输，作为通用生命周期元信息：

- `sessionToken` 继续负责协议会话及控制请求有效性。
- 连接代号由真实 Profile 连接事件建立；适配器替换、协议恢复、设置变化不生成新代号。
- 真实断开结束连接代号；多 Profile 接入时须先按物理设备归并，不能把 A2DP/HFP 各算一次。
- 进程启动后的已连接设备补录属于状态恢复，不作为新的连接事件。
- 会话结束明确记录原因，至少区分真实断开、暂停、适配器重选和系统接管。

这些信息属于会话／传输信封，不加入厂商 `DeviceFeatureState`，不让 Adapter 计算连接代号。
本轮沿用当前已支持的连接观察入口，不借此扩大到尚未实现的 LE Audio 设备管理。

### 4.4 跨进程来源校验

现有 [StateBroadcaster](../system-module/src/main/java/dev/hyperears/bridge/StateBroadcaster.kt)
使用定向广播；定向包名本身不认证发送者。新增具有系统展示副作用的消费者前，须补齐：

1. 状态发送显式共享系统提供的发送方身份，接收端核对包名与 UID 对应关系。
   现有 MiLink 等状态接收端同步校验，避免归属判定建立在未经认证的候选快照上。
2. `com.android.bluetooth` 与 `com.xiaomi.bluetooth` 可能共享 UID；只检查数字 UID 不足以区分发送职责。
   无有效来源时不触发新展示，不信任 Intent 中自填的包名。
3. 复用会话令牌、递增版本、已退休令牌拒绝规则，并区分实时更新与启动快照回复。
4. 归属与当前状态须一致发布；旧会话的模块归属不能为新会话授权。
5. 宿主重建先完成当前状态同步，建立处理基线，再接受实时事件；补发状态不能补弹旧连接。
6. 控制和状态请求仍使用限定的目标包及现有序列化契约，不广播原始协议帧。
7. 窗口启动使用一次性授权，绑定真实地址、生产者生命周期、当前会话、连接代号与有效期。
   已认证状态由原生宿主用 `ActivityOptions.setShareIdentityEnabled(true)` 启动窗口，
   UI 侧核对系统提供的 `Activity.getInitialCaller()` 包名与 UID，再消费一次性窗口 ID 和快照。
   Intent 自带的随机字符串不能自行证明授权。取消、系统接管或生产者退出时撤销。
   实验中的 nonce 只是测试夹具；分支实现使用上述 Android 平台调用方认证。

生产者进程退出不能依赖“最终断开广播一定送达”。沿用项目已有 Binder 生命周期令牌的模式，
在受信任的注册消息中附带进程令牌，以 `linkToDeath` 撤销该生产者的展示授权；
不增加定时心跳。令牌属于传输元信息，不进入 `DeviceFeatureState`。

可以复用项目已有归属广播使用的 `setShareIdentityEnabled(true)` 方式。
该选项及接收端来源 API 已由 Android 文档定义，不需要自定义一个声称可信的字符串字段。
[Android BroadcastOptions 文档](https://developer.android.com/reference/android/app/BroadcastOptions#setShareIdentityEnabled(boolean))

## 5. 原生宿主与 Hook 边界

新增作用域限定为提供原生耳机服务的 `com.xiaomi.bluetooth`，并核对实际承载进程。
不新增 SystemUI、系统设置或厂商控制 App 的展示 Hook。现有蓝牙、MiLink 路径继续各自承担原职责。

| 边界 | 允许方式 | 验证要求 |
| --- | --- | --- |
| 宿主服务生命周期 | 精确类与 `onCreate` / `onDestroy`，取得真实服务实例 | 仅管理本模块登记；不替换宿主服务 |
| 动态插件加载 | 已验证的插件加载完成回调，或现成插件服务生命周期 | 原生样本有 `SampleSplitLoadReporter.onLoadOK`；需验证实际回调及 ClassLoader |
| 展示／状态入口 | 语义明确的方法、精确参数及目标设备校验 | 方法、读写集合、线程和退出行为均有证据 |
| 通知动作 | 精确的通知语义 Receiver 或处理方法，仅匹配模块当前展示 | 样本有 `BluetoothHeadsetServicePlugin.HeadSetReceiver.onReceive` |
| 资源 | 宿主原有提示动画，以及 Adapter 声明的模块图片 | 只用于展示；不写入身份缓存或扩大能力 |
| 版本兼容 | 精确成员验证；确有必要时使用经审核、唯一且缓存的 DEX 指纹 | 版本号只辅助定位；不按“OS4 都相同”处理 |

不增加全局 `ClassLoader.loadClass` Hook、方法签名遍历、混淆字段猜测、View 树扫描、
延后 `post` 修布局、宿主加载轮询或任意 Socket 数据捕获。
现有卡片在已验证资源 ID 上的局部扩展经验，不构成遍历原生弹窗布局的依据。

仅有可读的方法名仍不足以认定稳定。每个启用入口都需记录：宿主版本／插件指纹、方法签名、
参数语义、数据来源、读写副作用、执行线程、销毁路径和原生设备旁路条件。
后端分别检查连接提示、电量弹窗、详情通知是否可用；一个入口失效不关闭其他已验证功能。

### 5.1 AirPods 窗口的语义 Hook

以下全部位于 `com.xiaomi.bluetooth:ui`。仅有包名和地址匹配不足以接管，必须已经为当前
Controller 建立有效的窗口绑定。其他实例立即执行原实现。

| 方法 | 本模块窗口的处理 | 范围与释放 |
| --- | --- | --- |
| `MiuiAirPodsFastConnectController.onActivityCreate()` | 校验一次性授权和当前物理连接，绑定本 Controller 与其 ServiceConnection；执行原初始化 | 绑定按对象身份区分；创建失败立即撤销 |
| `AirPodsInfo.buildPodsStatus(String)` | 在上述初始化调用范围内，用同一份快照设置连接、电量与充电初值 | 使用可恢复的线程局部作用域；其他模型创建不受影响 |
| `ContextWrapper.bindService(Intent, ServiceConnection, int)` | 仅匹配已授权 Activity、它自身的 ServiceConnection 及 FastConnect 目标；派发本地绑定完成回调 | 其余实例与目标原样执行；不启动真实 FastConnect 服务 |
| `ContextWrapper.unbindService(ServiceConnection)` | 仅释放上述本地绑定 | 原生设备的绑定／解绑不受影响 |
| `MiuiAirPodsFastConnectController.getAirPodsState(String)` | 当前窗口且地址一致时，返回已有快照的原生格式 | 不 Hook ContentProvider，不写设备缓存 |
| `MiuiAirPodsFastConnectController.loadDynamicPicture(String)` | 当前窗口使用原生静态资源初始化，跳过 Apple 云图片下载 | 不修改原生全局资源目录 |
| `MiuiAirPodsFastConnectController.initParameter()` | 通过原生图片字段提供 Adapter 声明的耳机／盒图 | 不修改 View 树；缺失图片按形态回退 |
| `MiuiAirPodsFastConnectController.setConnectDeviceDialog(int)` | 原生窗口创建后，为本 Controller 的内容字段 `mView` 绑定设置跳转 | 仅模块有效窗口且内容无原生点击动作时绑定；布局替换、关闭和销毁时撤销并恢复属性 |
| `MiuiAirPodsFastConnectController.setConnectSuccessLayoutDetail(View)` | 原生绘制后按已知盒电量调整盒图片、电量区域的可见性 | 仅有效绑定的当前根视图；明确资源名及控件类型校验失败时保留原生行为 |
| `MiuiAirPodsFastConnectController.onActivityDestroy()` | 先执行原注销、解绑和资源清理，再撤销授权与所有绑定引用 | `finally` 释放，旧回调不能再次刷新 |

最初独立实验通过替换 ServiceConnection 回调参数验证了本地接口；模块实现进一步将真实服务
绑定改成上述两个实例限定的本地绑定 Hook，避免依赖扫描服务。两个 Android 方法虽然定义在
公共基类中，处理条件要求 Activity 对象、Connection 对象和目标服务同时精确匹配。
这些新增路径和资源 Hook 需要完整测试包复核。入口依赖字段包括：
`mActivityContext`、`mFastConnectServiceConnection`、`mFastConnectClientCallBack`、`mAirPodsInfo`，
以及 native interface / callback 的完整方法签名。缺少任一必需成员时，不开放这一弹窗后端。
实验用的截图绘制不进入正式实现；内容点击只使用已确认的 Controller 字段，不扫描 View 树。

### 5.2 窗口专属的本地服务接口

原 Controller 通过 `IFastConnectService.Stub.asInterface` 获取服务。后端使用宿主 ClassLoader
中的准确接口创建本地实现，并通过 Binder 的 local-interface 机制交给该 Controller。
按已核实的方法名和参数处理调用，无需手写事务编号、Parcel 编解码或枚举未知方法猜用途。

| 调用 | 处理 |
| --- | --- |
| `registerForAirPods` | 保存这个窗口的原生 callback，不注册到原生共享 Helper |
| `getDeviceConnectStateForAirPods` | 返回当前绑定的真实物理连接状态；地址不一致时拒绝 |
| `unregisterForAirPods` | 幂等注销当前窗口 callback |
| `notifyActivityIsFrontForAirPods(false)` | 使用当前窗口的原生关闭回调，遵循原生退到后台即关闭的语义 |
| 配对／连接写操作 | 关闭当前展示并报告不支持，不进入原生配对流程 |
| 未验证的方法 | 停用当前展示并清理；不能转发给真实服务猜测执行 |

`asBinder`、对象相等性等基础方法按接口契约实现。回调不得在持锁状态下调用，销毁后迟到请求
一律无副作用。这个接口只承担系统展示兼容，属于 `HyperOsHeadsetBridge` 内部；
它不替代现有 `ProtocolSession`，也不让各品牌 Adapter 实现 Android Binder。

原 Controller 仍执行 ServiceConnection 的已绑定／解绑生命周期，绑定对象为窗口本地接口。
原生扫描服务不会因这个窗口被启动。本地接口阻止 Apple Helper 注册与配对行为。
实现不使用实验用的 root `startservice`、暖启动 Activity 或修改系统开关；
原系统关闭 FastConnect 时，接受宿主限制，不强制改开关。

### 5.3 动态插件初始化

主包 `MiuiApplication` 经 Qigsaw 加载功能插件；当前样本在
`SampleSplitLoadReporter.onLoadOK(String, List, long)` 收到加载完成事件。
可在准确的生命周期入口完成一次成员解析，使用实际宿主 ClassLoader 安装上述 Hook。
已经加载时进行一次就绪检测，未加载时等待这个语义事件；不全局拦截 `ClassLoader.loadClass`。
该回调及接口已静态确认，LSPosed 冷启动顺序仍待单独验证，不能用 Frida 附加成功代替。

## 6. 三种展示的具体方案

### 6.1 连接提示／超级岛

模块复用现有 `MiuiBluetoothNotification.showConnectToastForAirPods`。
在本模块的一次同步调用范围内，`OfflineFindProvider.getAirPodsState` 为当前地址返回已接受
电量；其余调用读取原数据。该路径使用宿主现有动画和消息生命周期，不写 Apple Provider，
不拼装 `island_param`。连接记录、原生窗口占用、屏幕及锁屏条件在提交前核对，
并保留原方法中的系统开关检查。

同一真实连接最多提交一次短暂提示。首次可展示时使用当前可用的状态，不等待所有私有能力确认。
状态补发本身不触发提示；已经观测到的新连接等待归属或电量期间，补发不能消耗其展示机会。
只有补发、没有观测到新连接的恢复场景仍保持静默。新连接的 10 秒有效期不因补发而延长。
成功超级岛要求已有可用耳机电量；只有盒电量或未知整机电量时不提交。后续正常状态事件
带回电量后，在连接有效期内继续判断，不添加固定等待或轮询。实机已确认未知整机电量会
让原生生成缺少右侧内容的单图标参数，SystemUI 随后拒绝解析。
该短提示使用提交时的电量快照，后续电量不重新提交超级岛，只更新电量弹窗和通知。
详细日志记录原生登记读取结果，以及展示等待原因、连接年龄、电量来源和提交结果。
`submitted` 只表示已调用宿主入口，不表示已收到 SystemUI 的显示确认。
私有通道重连、Adapter 升级及厂商 App 退出不再次提交。
流转过程已有原生提示时，本模块不抢先建立另一个显示流程；宿主原有连接记录和去重标志不得重置。

实现保留以下边界，完整测试包需继续复核：

1. 只读取原生连接／流转记录，不覆盖其 requestFlag 或计数。
2. 展示资源选择仅在请求内生效，不调用会把它永久存为真实型号的方法。
   `MiLinkCarrierIdentity` 只服务既有卡片承载，不直接充当 FastConnect／通知的设备身份。
3. 异步提示读取的电量与当前快照一致，不被旧缓存覆盖；佩戴未知时使用原生允许的未知／不支持路径。

本轮不承诺没有有效电量时一定显示百分比，也不为取得岛动画伪造佩戴状态。
若宿主仅能在伪造身份或佩戴条件下工作，该版本的对应提示暂不启用。

### 6.2 连接后的原生电量弹窗

已验证的调用链为：

```text
当前已接受快照 + 本次窗口授权
  → 原生 MiuiFastConnectActivity
  → 工厂按本窗口选择值 16 创建 AirPods Controller
  → onActivityCreate 建立实例绑定
  → buildPodsStatus 使用真实连接及已知电量初始化
  → 原 ServiceConnection 绑定到窗口专属的本地服务接口
  → 原 Controller 读取当前窗口状态并绘制
  → 新状态通过原生 deviceBatteryStateUpdate 刷新
  → closeDialogForAirPods / 原生用户关闭
  → onActivityDestroy 注销、解绑、清理
```

选择值 16 只决定这次 Activity 使用哪个 Controller，不写全局 `mProtocolVersion`，
也不把该设备登记为 Apple。真实苹果设备仍由官方负责，HyperEars 的设备匹配链保持不含苹果。

打开窗口时先使用当前快照；需要刷新时，通过已有 `StandardControlRequest.Refresh` 请求一次，
保留原有合并、能力、退避及 Adapter 事件策略。后续仅处理已接受的状态更新。
Controller 的初始化、getter 和 callback 统一读取当前绑定的同一版本，避免第一帧 0% 或下一帧
又被 Apple Provider 空值覆盖。`null` 映射为原生 `-` / 模型 `-1`；不能保留旧百分比。

原生双耳模板只有在盒电量已知，且至少一只耳机带充电位时才显示盒区域。
实验已分别验证不充电、充电和清空组件的结果。自 `2.8.0-native-test.5` 起，针对模块拥有的
窗口，在原生电量绘制完成后按有效盒电量调整两个既有盒区域的可见性，0% 也正常显示。
数字 ID 从已验证插件的具名 R 字段读取，并核对资源名称、类型和实际控件类型；不猜测 ID、
扫描布局结构或延迟修改。未知盒电量恢复隐藏；原生图片、电量文字和充电图标保持原实现。
真实 Apple 窗口不进入这项处理。入口或布局失配时，只停止盒区域扩展，保留原生弹窗。

点击本模块弹窗的耳机／电量内容区时，`HeadsetSettingsNavigator` 使用当前绑定的已接受状态及
最新“点击卡片‘更多设置’”选项打开目标，成功后通过原生关闭 callback 结束窗口。
原生关闭按钮、重试按钮和窗口外点击保留原有动作。内容字段不可用或已有原生点击监听时，
跳过新增导航；不影响电量显示。重新创建单电量／双耳布局时先移除旧监听再绑定新内容，
关闭或销毁时移除监听并恢复原点击与焦点属性，旧窗口不能再发起跳转。

`2.8.0-native-test.4` 的 vivo TWS Air3 Pro 实测再次确认：左右耳 100%、盒 99%、
两耳充电标志均为 false 时，数据已进入窗口回调，原生仍隐藏盒区域；这正是 `.5` 的修复场景。
连接超级岛的原生
耳机模板仅构造左右耳或整机内容，没有充电盒展示分支；不能把“数据已收到”等同于
“原生模板一定显示”。同版已捕获关闭电量通知时的 Bose 20% 超级岛，以及智能模式在
桌面选择弹窗、在应用内选择超级岛的日志与画面。

原生关闭行为与正式桥接的对应关系：

| 条件 | 处理 |
| --- | --- |
| 用户点击原生关闭按钮、原生 Dialog dismiss | 原 Controller 结束 Activity；解绑、注销与授权释放随后执行 |
| 点击本模块内容区并成功打开设置目标 | 撤销内容点击，通过原生 callback 关闭当前窗口 |
| Activity 退到后台 | 原 `onActivityStop` 发出前台状态通知，本地接口调用当前窗口的关闭 callback；已实测 |
| 真实断开、蓝牙关闭、暂停、系统接管或状态生产者死亡 | 展示协调器撤销当前绑定，通过同一个原生 callback 关闭；其中展示断开已用合成事件验证 |
| 旧版本、旧会话和已销毁窗口的更新 | 丢弃，不重新创建窗口 |
| 未预期的连接／配对请求或接口变化 | 关闭本窗口并停用该后端，保留原有 MiLink 集成 |

`onActivityStop` 虽传入 3000 ms，服务已绑定时原代码把延迟归零，不能描述为“固定 3 秒后退出”。
Controller 中的连接超时消息也不能当作已连接电量窗口的固定显示时长。
本方案保留原生用户关闭及后台关闭；自动连接时究竟选择短提示还是大弹窗，仍由第 6.1 节的
宿主决策与去重闭环约束，不能因为独立窗口能启动就每次同时弹两种 UI。

本机原 Activity 的销毁路径会在条件满足时退出 `:ui` 进程；实测日志中的这个进程退出是正常
生命周期。正式实现应在原销毁前后完成必要清理，不阻止 `System.exit` 维持模块窗口。

### 6.3 耳机详情通知

优先使用宿主耳机详情通知的原生样式与组件，更新当前已知电量。
进一步核实主包实现后，确认该组件同时有三路电量和 `singlebatteryheadset` 整机文本分支。
模块通过唯一 DEX 指纹解析创建、单设备取消、资格检查及
`getNotifyType`。整机文本只在本次通知创建调用范围内选择，不写真实型号缓存。

创建、更新、用户操作和清理作为一个能力验证：

- 开启设置时可为已经连接、已确认模块归属的设备创建常驻通知；不补发连接动画。
- 同一通知实例原位更新；保留原生删除动作。用户划掉后，后续状态回报可重新发布，
  不额外维护“本次连接已清除”的抑制状态，也不在清理动作发生时立即重发。
- 真实断开、关闭设置、暂停模块时清理模块拥有的通知与回调。
- 系统接管时停止提交；仅在确认仍为模块创建的实例时清理，避免取消系统新接管的通知。
- 原生“断开”使用经过核实的系统断开路径，不经私有 Socket，也不为执行动作补造 MMA 支持。
- 原生“详情”复用 `HeadsetSettingsNavigator`，按“点击卡片‘更多设置’”的当前选择打开
  该地址对应的系统蓝牙详情、厂商 App 或 HyperEars；目标不可用时回退到系统蓝牙详情。
  点击前核对通知实例、连接代号、当前归属、会话和设置，系统接管的同名通知不被覆盖。

`checkSupport` 的原生条件与创建／取消并不对称。若需要扩大它，仅允许在这个通知组件内，
针对当前模块拥有且明确登记的地址处理，并覆盖关闭后的清理阶段；
不得改动全局耳机支持判定、伪造 `feature+address` 或使用全设备取消函数。
如果不能稳定识别通知实例、点击对象或清理所有权，该后端的详情通知不开放。

早期实验按精确 APK 直接调用验证了通知创建与取消缺口。分支实现使用 DEX 唯一指纹，
不记录混淆类／方法名称。原生单设备取消在本次调用内获得同一展示资格；删除 Intent 和
对应的原生设备缓存清理由宿主负责，不再安装模块的通知删除 Hook 或删除广播接收器。
通知详情跳转复用卡片的目标选择与回退逻辑。断开动作保留原生处理。
创建前保护原来已有的通知，取消前核对当前通知的发布时间；系统接管时放弃修改同名原生实例。
上述新实现尚需实机验证其点击、划掉、断开和接管行为。

## 7. 生命周期、调度和失败行为

| 事件 | 短暂连接提示 | 已存在的电量弹窗／详情通知 |
| --- | --- | --- |
| 新的真实连接，归属未确认 | 暂不显示 | 不创建 |
| 在本次连接提示有效期内确认模块归属，宿主就绪 | 按原生策略提交一次 | 按设置和宿主能力创建 |
| 已接受电量变化 | 不重新触发 | 按变化刷新 |
| 私有握手失败／通道恢复 | 不重新触发 | 使用统一回退状态 |
| 厂商 App 退避与恢复 | 不重新触发 | 使用会话当前投影；不主动查询私有协议 |
| 暂停、重选适配器或禁用展示 | 不视为新的物理断连／重连 | 撤销相应展示与登记 |
| 系统确认接管 | 放弃待执行项 | 停止模块更新，按实例所有权清理 |
| 真实 Profile 断开／蓝牙关闭 | 取消待执行项 | 结束展示、释放对应记录 |
| 宿主或模块进程重建，收到启动快照 | 不补弹 | 完成归属和状态同步后恢复允许的常驻通知 |
| 熄屏期间原生拒绝提示 | 接受原生决定，不在解锁后重放 | 遵循系统通知策略 |

提示有效期属于展示新鲜度限制，用单调时钟衡量，数值由实际时序确定并明确记录。
它不修改协议握手超时，不延迟 Adapter 发布，也不延长为“迟早弹一次”。等待期间仅保留当前
连接最新状态和一个可取消的截止任务；过期、断开或接管即丢弃，没有后台重试循环。

并发使用一个串行的宿主协调队列；宿主要求的 UI／Handler 调用切换到相应线程。
排队操作在执行前再次核对会话、连接代号、版本、归属和设置。连续状态只保留最新投影，
断开、暂停和撤销不能被状态合并吞掉。

原生弹窗具有宿主全局显示标志和每设备连接记录，不能只检查本模块是否已有窗口。
正式自动触发须确认没有官方窗口或流转过程占用；只登记本次实际拥有的展示，销毁时仅释放
仍属于自己的标记。实验为了复位克隆过连接记录，生产代码禁止把整条旧记录覆盖回去，
否则会抹掉并发发生的原生流转更新。这个共存边界尚未完成端到端实测。

后端异常只停用失败的展示能力，不改变 Adapter、私有通道或 MiLink 发布。
不在主线程解析 DEX、读取资源目录或执行协议事务。解析与能力检测按宿主／插件版本缓存，
插件加载事件到达时更新一次。没有连接设备和待清理展示时，不保留周期任务。

## 8. 设置、日志与迁移

建议仅增加两项，放在模块的系统集成设置中，由 Material 3 与 Miuix 共用状态和行为：

| 设置 | 建议初始值 | 语义 |
| --- | --- | --- |
| 连接时显示 | 智能 | 智能／仅弹窗／仅超级岛／关闭；受宿主条件限制 |
| 耳机电量通知 | 关闭 | 连接期间显示受支持的原生电量通知 |

3.0.0 已实现这些设置；无历史选择时默认智能，已有 `OFF`、`SYSTEM_HINT`、
`BATTERY_POPUP` 存储值保留原选择，菜单顺序变化不影响持久化值。
数据进入 [ModuleSettings](../system-module/src/main/java/dev/hyperears/settings/ModuleSettings.kt)
及现有 RemotePreferences 流程，不进入主题设置，不另建一套配置存储。

设置页注明所需作用域；宿主入口缺失或初始化失败写入已开启的详细日志。
不能以“应用已安装”推断注入成功。保留用户选择与实际可用性两个概念，不因暂时未加载插件而改写选择。
智能模式只调用宿主 `HomeScreenChecker.isOnHomeOrCoverScreen(Context)`；旧插件按明确的
`isOnHomeScreen(Context)` 入口兼容。桌面／外屏桌面选择弹窗，其他应用选择超级岛。
这两个只读语义入口均不存在时，智能展示暂不提交；手动选择仍需通过对应展示后端的检查。
不调用 Apple Helper 的连接处理方法，不写它的设备、配对时间或扫描状态。
仅弹窗、仅超级岛也不能绕过锁屏、已有窗口、原生流转和真实连接检查。

连接提交机会只在后端成功提交后消耗。锁屏、窗口占用或组件数据暂不可用时，后续合法状态
事件仍可在连接有效期内触发；不添加轮询、延迟重试或过期补弹。
这一阶段不提供假佩戴、强制开盖、任意资源 ID 等调试选项给普通用户。

沿用现有详细日志开关和导出链路。开启后记录宿主版本、入口解析、归属来源、连接原因、
接受／拒绝的版本、状态投影、原生提交和清理结果；地址脱敏，不输出原始 Socket 数据。
分别记录“已提交原生服务”和“观测到实际显示”；没有稳定显示回执时，不能把提交成功记成显示成功。
关闭详细日志时，不产生这部分模块诊断记录。

## 9. 实施顺序与验收

### 9.1 已完成：独立窗口验证

已在本地忽略的研究目录完成第 2.3 节实验，未修改设备 Adapter、协议、正式 Hook 或设置。
AirPods 窗口已验证初始化、刷新、未知值、实例隔离及退出；原生短提示与详情通知有各自明确的
部分验证结果。网络中断未覆盖成功记录，补测采用独立结果文件并保存连续日志。

### 9.2 下一步：自动入口和共存验证

以下边界继续作为不同设备与宿主版本的回归项目，不代表每个组合均已实测：

1. MiLink 未启动时，原生宿主登记读取及带会话校验的结果回传是否满足第 4.1 节要求。
2. 动态插件冷启动、服务首次绑定／销毁，以及第 5.1 节语义 Hook 的安装时机。
3. 不修改系统开关的正常连接提示入口、原生窗口占用、与 MiLink 流转去重。
4. 真实设备名称与形态资源；TWS 整机回退不能误显示为两份电量或头戴外观。
5. 官方设备窗口与本模块窗口共存；真实断开、熄屏和进程死亡的清理。

若有官方耳机可用，记录官方原流程作对照；没有该硬件时，明确保留这一验证缺口，
不把代码推断标为官方实机结果。某一能力无法满足边界时停止该能力的实现，不扩大 Hook 面补齐外观。

### 9.3 正式实现：共享状态与已验证后端

3.0.0 的完整测试包已在本机 HyperOS 4 验证 Bose QuietComfort Headphones 的整机电量提示、
vivo TWS Air3 Pro 的双耳弹窗与盒电量显示，以及智能模式的场景选择。
关闭电量通知时的 Bose 20% 超级岛已有画面与日志；`.5` 的已知盒电量显示修复获得维护者实机确认。
单元测试覆盖资源全型号继承、整机与组件投影、未知电量、零电量、显示条件、连接去重及归属返回码。
构建、Lint 和单元测试用于验证实现；真实 Apple 共存、多设备并发及更多宿主版本仍需扩大实测覆盖。

补齐状态来源认证、已有归属结论传播和真实连接元信息，复用当前序列化及状态接受规则。
保持所有型号协议实现和控制策略不变。为状态来源、归属竞争、会话重选、启动补发、
提示去重及关闭清理编写针对性测试；不以重写全部适配器来引入展示功能。

正式改动集中在现有状态传输和 `system-module` 的原生展示后端，保留各型号 Adapter 与
ProtocolSession 实现。连接提示、电量窗口、独立详情通知及对应设置、日志一同交付。
通知保留原生删除动作，后续状态回报可以重发；清理及多设备行为持续按下表回归。
每项完成定向测试和必要的模块编译后再做签名实机包，不为文档或参数整理重复全量构建。

| 验证场景 | 通过条件 |
| --- | --- |
| 系统已支持的耳机 | 原始归属及官方展示不变，无模块重复提示 |
| 标准整机电量设备 | 保留标准电量；不伪装成两只耳机 |
| 私有电量逐项到达／单耳／盒未知 | 正确增量展示和清除未知项，不保留旧组件电量 |
| Adapter `HOLD` 与后续接受 | 系统 UI 与卡片、主页使用同一已接受版本 |
| 同次连接的协议升级、私有重连、退避恢复 | 无新连接动画，无重复通知 |
| 关闭／重选 Adapter、暂停再恢复 | 不制造新的物理连接事件 |
| 多设备与乱序数据 | 按地址、会话和版本隔离，不串设备、不接受旧令牌 |
| 系统归属后到 | 停止模块投影，不能由迟到的模块授权反转 |
| 用户划掉通知、关闭设置、系统接管 | 正确清理；不取消另一台设备或系统新建的通知 |
| 熄屏、未解锁、系统提示开关关闭 | 遵循原生限制，不解锁补弹 |
| 插件延迟加载、宿主重启 | 不轮询、不补播旧动画；恢复允许的当前通知 |
| 老／新宿主与不匹配指纹 | 已验证功能分别启用；未知入口保留现有 MiLink 功能 |
| 来源缺失、伪造广播、过期会话 | 不产生系统展示或控制副作用 |

真实设备上的协议、生命周期和卡片行为变化仍遵循贡献规则中的维护版复核要求。
通过单元测试或构建不代表上述原生显示验收已经完成。
