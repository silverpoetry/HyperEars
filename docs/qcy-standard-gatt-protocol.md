# QCY 标准 GATT 协议适配

HyperEars 根据 QCYpods 固定提交实现组件电量、原生三态噪声控制，以及逐项回报确认的
低延迟、睡眠、LDAC、双设备、动态 EQ、自适应音量、厂商空间音效和耳机端均衡器。
这些功能的公开源码证据不代表每个 QCY 型号均支持，也不代替最终版本的实机复核。

## 1. 候选选择

当前登记的具体型号为 Crossky C50S；社区报告的蓝牙名称为 `QYCC50S`。具体型号 Adapter
接受以下规范化名称：

- `qycc50s`；
- `crosskyc50s`；
- `qcycrosskyc50s`。

名称以 `QCY` 或 `Crossky` 开头的标准蓝牙耳机可以进入同协议家族探测。名称只用于选择
候选 Adapter，不会直接开放私有电量或噪声控制。HyperOS 已原生接管的耳机仍由平台保留，
不会进入 QCY 匹配链。

## 2. GATT 端点

公开协议使用以下服务和特征：

| 用途 | UUID |
|---|---|
| 主服务 | `0000A001-0000-1000-8000-00805F9B34FB` |
| 命令写入 | `00001001-0000-1000-8000-00805F9B34FB` |
| 状态通知 | `00001002-0000-1000-8000-00805F9B34FB` |

Adapter 按顺序尝试两个端点：

1. 当前 A2DP/HFP 音频设备；
2. 与音频设备关联的伴生 BLE 控制端点。

伴生端点解析由通用 `GattPeerSelection.CompanionDevice` 承担。运行层先检查已配对设备；仍未
找到时，按厂商数据 ID `0x521C` 进行一次最长 8 秒的定向扫描。QCY Adapter 只接受以下
关联证据之一：

- 候选名称精确等于当前音频设备名称加 `-APP`；
- 广播中的控制地址或关联地址等于当前音频设备地址；
- 当前音频设备和候选端点均具有明确的 QCY 名称，且候选广播同时带有 `0x521C` 厂商数据。

单独出现通用服务 UUID 或 `0x521C` 厂商数据不足以把一个无关设备判定为 QCY 耳机。
扫描在匹配、超时、取消或会话关闭时立即停止，不会形成后台持续扫描。

## 3. 帧格式

通知和命令均使用可连续承载多个命令块的字节流：

```text
FF LL [CC NN parameters...]...
```

- `FF`：帧起始标记；
- `LL`：后续全部命令块的总字节数；
- `CC`：命令编号；
- `NN`：当前命令参数长度；
- `parameters`：恰好为 `NN` 字节。

流式解码器按外层和内层长度同时校验分片、粘包与多命令帧。长度不完整、参数越界或字段
非法的帧不会产生协议事件，也不能确认能力。

读取状态使用请求命令 `FE`：

```text
FF 03 FE 01 CC
```

## 4. 电量

电量命令编号为 `2F`：

```text
查询：FF 03 FE 01 2F
响应：FF 05 2F 03 LL RR CC
```

`LL`、`RR`、`CC` 分别表示左耳、右耳和充电盒。每个字节的低 7 位为 `0..100` 电量，
最高位表示充电状态。至少一个组件值合法时才发布私有电量；没有合法响应前始终保留 Android
系统整机电量回退。

## 5. 噪声模式

噪声命令编号为 `0C`：

```text
查询：FF 03 FE 01 0C
设置：FF 03 0C 01 MM
```

| `MM` | 公开协议语义 | HyperEars 投影 |
|---|---|---|
| `00` | 关闭 | 关闭 |
| `01` | 降噪 | 降噪 |
| `02` | 户外降噪 | 降噪 |
| `03` | 通透 | 通透 |

MiLink 原生卡片使用三态控制，因此 HyperEars 只写入 `00`、`01`、`03`。若耳机回报 `02`，
当前状态投影为降噪，不额外注入控件。每次设置后通过统一回读流程查询 `0C`，只在收到合法
设备状态时更新卡片。

## 6. 能力与失败回退

`QcyProtocolSession` 初始发送一轮电量、噪声与可选设置的只读查询，不建立后台轮询。每项能力独立确认：

- 合法 `2F` 响应把电量来源从系统整机升级为私有组件；
- 合法 `0C` 响应开放原生三态噪声控制；
- 任一合法状态帧可以确认当前传输承载 QCY 协议；
- 某类响应缺失时，该类私有能力保持关闭；
- 当前设备和伴生端点均失败时，直接切换到标准耳机 Adapter。

标准回退仍提供 MiLink 流转、系统音量和 Android 系统整机电量，不建立 QCY 私有通道。

## 7. 代码边界

- `QcyAdvertisementCodec`：解析公开的广播地址布局；
- `QcyWireCodec`：纯字节帧、流式解码、严格状态解析和命令编码；
- `QcyProtocolSession`：初始查询、能力证据、控制回读和状态事件；
- `QcyEarbudAdapter` 层级：型号/家族匹配、端点候选、控制 App 与失败回退；
- Android 运行层：执行 Adapter 声明的有界端点解析，不包含 QCY 名称或协议字段；
- `QcyFeatures`：带命名空间的类型化状态与控制请求；
- MiLink：复用宿主原生噪声控件并挂接高级设置入口；没有噪声证据时只提供设置入口。
  弹层观察当前设备会话，控制权让出、断开、会话令牌变化和解绑时释放观察者与 UI 超时任务。

## 8. 可选设置与均衡器

普通开关低延迟 `09`、睡眠 `10`、LDAC `23`、双设备 `24` 的参数仅接受开启 `01`、
关闭 `02`；动态 EQ `27`、自适应音量 `40` 则仅接受开启 `01`、关闭 `00`。其他值和
错误长度不发布状态。LDAC 是耳机配置开关，不宣称 Android 当前协商编解码器已改变。

空间音效 `2D` 的已知值为 `0..2`；UI 显示关闭、模式 1、模式 2，不把模式 2 推断为
各型号均具备物理头部跟踪。该状态保存在 QCY 专属模型，不投影为通用头部跟踪能力。

均衡器 `20` 的一字节预设值为 `0` 自定义、`1` 默认、`2` 流行、`3` 低音、`4` 摇滚、
`5` 柔和、`6` 古典、`10` 空间。`22` 可以回报单字节预设或完整 PEQ 参数；完整参数为
预设 ID、signed LE16 总增益（百分之一 dB），再按频率 unsigned LE16、增益 signed LE16
（百分之一 dB）、Q unsigned LE16（百分之一）、滤波类型一字节排列每个七字节频段。

`20` 与 `22` 均可确认 EQ 预设状态，按上游控制器通过 `20` 写预设，最新有效回报更新选择。
只有完整有效 `22` 证据才开放
PEQ 编辑器，单字节或截断参数不虚构频段值。回报显示保留完整频率、增益、Q 和类型数值。
编辑器实现上游十段自定义曲线：31、62、125、250、500、1000、2000、4000、8000、16000 Hz，
每段整数增益 -8..8 dB、Q=1、滤波类型 2、总增益 0。未应用数值明确标为草稿，只有点击
应用才发送到耳机；这不是手机端软件 EQ。当前回报不是同形状自定义曲线时，新草稿从零开始，
不会把它显示成耳机当前设置。

所有控制通过 `QcyControlRequest`、Adapter 会话门控和统一回读执行，不乐观更新。
高级弹层显示等待回报、确认或五秒未确认提示；该超时只更新 UI，不轮询、不重试协议写入。
重连清除所有 QCY 专属能力与旧状态。固件升级及罕见校准继续使用现有厂商 App 交接入口。
