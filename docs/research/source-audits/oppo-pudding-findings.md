## Stability practices: adapt protocol facts, do not replace local lifecycle wholesale

- Upstream `RfcommController.kt:709-724` sends each InputStream.read result straight to handleOppoPacket. It does not stream-reassemble frames at this boundary; fragments/coalesced frames are a risk. Retain local bounded `OppoWireCodec.Decoder` framing and strict shape validation.
- Upstream `RfcommController.kt:664-692` schedules a fixed reconnect delay and increments a counter without using it as a retry ceiling there. Retain HyperEars bounded retry/dormant wake and control-app ownership backoff.
- Upstream `SettingsHeadsetHook.kt:22,39-47` polls every 3000 ms while tracked fragments remain. This conflicts with local CONTRIBUTING rule against permanent model/UI polling. Use snapshot/event subscriptions and one-shot bounded queries.
- Upstream broadly forces support/carrier results and has current-device singleton state. Native projection should be per-address, scoped to the session, evidence-gated, and leave official native devices untouched; do not copy carrier-ID-only match rules.
- Local OPPO decoder and notification subscription are already better foundations. Add vendor-typed ControlRequest/DeviceFeatureState for advanced features, require corresponding valid reads before enabling a control, and confirm writes with acknowledgements/readback.

## PuddingPods: useful documented protocol delta, source absent

`PUDDING_ADAPTATION.md:14-24` maps off=00, adaptive ANC=01, transparency=02, wind=03, basic ANC=04. Local `protocol/.../MoondropPuddingWireCodec.kt:18-21` recognizes only 00/01/02 and names 01 generic ANC; reads of 03/04 are discarded. This is a concrete capability gap, but local Pudding and Robin deliberately share the protocol session and wire enum: avoid broadening Robin to Pudding-only modes without evidence.

`PUDDING_ADAPTATION.md:30-36` gives an additional battery query and delta-merging behavior; local battery parser requires exactly six bytes with ordered 1/2/3 keys (`MoondropPuddingWireCodec.kt:81-86`). Variable-component reports are a candidate compatibility improvement, requiring captured positive and malformed examples before loosening shape checks.

`PUDDING_ADAPTATION.md:40-43` gives gain query 00 1D 1E 01 / set 00 1D 1E 02 level (0/1/2 low/medium/high) and LED query 00 1D 26 01 / set 00 1D 26 02 state (0/1). Published docs do not fully specify acknowledgement, error, and response semantics. Model-specific typed state/requests and actual readback evidence are needed before enabled controls.

Native UI nuance: `PUDDING_ADAPTATION.md:58-63` distinguishes native MiuiHeadsetActivity from BluetoothDeviceDetailsFragment and mentions Settings-process navigation bridge. `:66-69` explicitly hides the template's native four-step ANC slider/labels and inserts its own three-segment controls; `:72-76` redirects MiuiHeadsetActivity to PuddingDetailActivity. Thus the project's claim of system integration is not evidence for the user's stronger requirement that every function use actual native widgets. It also says version 3.49 in a document whose README/current routing is 3.45, an unresolved documentation version inconsistency.

Local Pudding already has strict handshake, fragmented stream parsing, event-scoped bounded battery bootstrap and mode stabilization (600 ms then 500/700/900/1200 ms); retain this. Do not replace locally recorded hardware behavior with unverified upstream prose. No device acceptance was run in this audit.
