# ROSE Ceramics X 协议与展示

## 已支持能力

`RoseLuliXAdapter` 按精确名称选择候选，经过有界扫描关联音频设备的 GATT 端点；
`RoseCeramicsXWireCodec` 解析该端点的模式响应。初始保留 Android 整机电量；合法模式
响应确认后开放降噪、关闭、通透、抗风噪。私有左右耳与充电盒电量尚未实现。

| 项目 | 已确认值 |
| --- | --- |
| 服务 / 写 / 通知 UUID | `FDB3` / `FF16` / `FF17`，均使用 Bluetooth Base UUID |
| 写 / 通知属性实例 | `0x0015` / `0x0017` |
| 查询模式 | `00 27 01 00 01 0C` |
| 查询响应 / 主动报告 | `00 27/28 02 00 03 0C 01 <mode>` |
| 设置模式 | `00 2C 01 00 01 <mode>` |
| 模式值 | `00` 抗风噪、`01` 降噪、`02` 通透、`03` 关闭 |

证据来自 [原始适配 PR #39](https://github.com/silverpoetry/HyperEars/pull/39)；
[PR #76](https://github.com/silverpoetry/HyperEars/pull/76) 补充了部分固件的同地址端点及
广播长度字段。端点维护版复核不补足尚未定义的电量字段语义。

## 2026-10-28 日志核查

反馈运行 HyperEars 3.1.0 / Android 17。截图为 16:49，导出日志记录从 17:06 开始，
因此不能把截图对应到某一次具体日志事件。下列时间均为日志设备时间（UTC+8）。

| 时段 | 日志事实 | 说明 |
| --- | --- | --- |
| 17:09–17:14 | 多次关联到伴生端点，并收到合法 `0x27` 通透响应；没有原生归属确认记录 | 私有模式握手成功，展示准入仍在等待 MiLink |
| 18:03:05、13、20 | 原始准入返回 `0`，模块归属确认；智能模式选择桌面弹窗，UI 创建窗口并更新电量 | 弹窗入口和更新链路可用 |
| 18:03:29–31 | 智能模式选择超级岛；整机电量更新为 100% 后仍因 `TWS single=true` 拒绝提交 | 原单电量 TWS 限制影响这一型号及其他整机回退设备 |

整份日志收到 24 条 `00 27 02 00 03 0C 01 02` 模式响应，以及 16 条
`09 FF 00 00 01 09 01 0B 00 00 1E` 报告。后者按已有 EARFREE 帧结构可以校验长度及
校验和，但分组为 `09`、命令为 `01`、载荷只有 `00`，不符合该协议的电量响应定义。
不将该报告推定为盒电量，也不据此向琉璃 X 发送其他型号的查询命令。

伴生广播尾部曾出现 `05 64 64 22` 和 `05 64 64 00`。目前仅确认该广播用于端点关联；
左右耳顺序、末字节含义、无效值和充电位尚未验证。`64` 恰好与当前整机 100% 相同，
不足以证明这些字段就是独立组件电量。

因此，本次保留整机电量投影：一个百分比，盒电量未知时隐藏盒区域。共用展示修复
与协议电量扩展分别验证；没有新增私有写入或持续扫描。

## 补足组件电量所需证据

使用厂商 App 与系统 Bluetooth HCI 记录，保留操作时间及 App 显示的真实数值：

1. 两耳电量明显不同时连接，确认左右字段顺序；重复一次电量变化。
2. 开盒、合盒、单耳入盒、双耳入盒各记录一次，区分盒电量与连接／充电状态位。
3. 记录厂商 App 查询电量的完整写入及通知，确认查询命令、长度、校验和、未知值及 0% 语义。
4. 日志中的个人地址脱敏为一致的合成地址，保留音频端点与伴生端点的关联关系。

字段确认后，字节解析进入 WireCodec，状态报告由 ProtocolSession 交给 Adapter 接受并
开放私有电量；弹窗、通知和看板继续消费同一份状态，无需增加型号专用展示分支。
