## 识别与确认

官方 Galaxy Buds / Samsung Galaxy Buds 名称及 SM-R 编号选择具体型号候选；
官方名称可带四位十六进制设备后缀。自定义名称中的型号提示须同时具备三星专属服务。
仅具备专属 UUID 的未知型号选择家族回退；标准 SPP UUID 本身不证明三星身份。

候选 Adapter 保留 Android 系统整机电量、音量和流转。CRC 有效的设备状态逐项确认私有
电量、噪声和设置；协议断开或让出控制权时清除私有状态。控制 App 只负责导航与退避，
不参与型号识别。Live / Pro 使用标准 SPP，其余型号使用以下专属服务。

## 传输与帧

- RFCOMM 服务 UUID：`2e73a4ad-332d-41fc-90e2-16bef06523f2`
- 帧：`FD [size:2LE] [message id] [payload] [crc16:2LE] DD`
- `size` 包含 message id、payload 和 CRC；最低为 3。
- CRC 为 CRC16-XMODEM（多项式 `0x1021`、初值 `0`），覆盖 message id 与 payload。
- 解码器按连续字节流工作，处理拆包、粘包、前导噪声、非法长度和错误 CRC；只有完整且校验
  通过的状态帧可以成为 Adapter 的能力证据。

## 控制与状态

- `0x90` 写入触控锁与完整手势设置；Buds2 Pro 的 ACK 回显触控启用位，
  `00` 表示锁定，`01` 表示解锁。Live / Pro 使用各自传统单字节锁定格式。
- `0x95` 单独控制耳缘双击音量。卡片关闭触控总开关时一并关闭；同一会话重新开启时恢复
  锁定前已确认的偏好，重连清除该会话记录。
- `0x92` 写入左右长按动作。卡片提交单耳类型化请求，协议会话合并另一耳尚待确认目标
  或已确认值，再生成成对命令，避免连续修改左右耳覆盖前一次操作。
- Buds2 / Buds2 Pro / Buds FE 的有效组合状态允许 `0x79` 写入；左侧三个布尔字节
  后接右侧三个。扩展状态 `payload[21]` 高半字节为左侧，低半字节为右侧，
  位 2/1/0 对应降噪、环境声、关闭。缺失或未知组合保持不可写。
- 长按动作按参考流程发送 `0x92`，必要时跟随 `0x79`，指令组内不插入模块侧等待。
  `0x88` 为管理器信息，不能作为保存或查询命令。
- 型号支持范围由 Adapter 校验，命令由 ProtocolSession 编码。界面发送请求后只读取
  Adapter 发布的状态，不保存另一份目标、不安排延迟恢复开关或定时查询。
- 长按动作及组合采用写入后发布目标的显示策略；实际确认值保留在协议状态中，ACK 或
  匹配完整回报才确认。迟到旧值保护限于本会话的 90 秒窗口，过期在下次协议事件或控制
  编码时清除目标。该窗口不创建常驻后台任务。
- 连续修改手势使用会话内未确认位合并完整命令。非法设置或 ACK 不替换已确认设置；
  合法独立电量与噪声字段仍可接受。

扩展设置校验 EQ 0–5、长按动作 1–4、环境声等级 0–3。Buds2 Pro 超高环境声须在
revision 13+ 且 `payload[45]` 存在、取值为 0/1 时开放。Pro 耳缘音量须 revision 7+
且对应布尔字段存在。新款要求合法共同报告，不外推可选设置、充电标志、自适应控制或
旧六字节噪声组合格式。

## 卡片与生命周期

复用原生噪声卡片和统一触控开关扩展。标题保留在布局中参与测量，多项扩展时按原有规则
隐藏标题；不按标题文字遍历布局。触控标签打开分级菜单，菜单按设备订阅状态；
关闭、解绑、断开或打开失败时解除订阅。普通风噪和游戏模式开关继续使用统一状态投影。

Galaxy Wearable 及各型号控制插件在统一控制 App 目录声明。“停止厂商应用”从该目录生成
包名列表，覆盖所有声明的控制器。退出退避、会话重建与其他 Adapter 共用既有生命周期。

## 最终维护版复核

请记录耳机固件、HyperOS、Android 和 MiLink 版本，验证：

1. 连接后电量、噪声及专属设置逐项开放；未回报字段保持关闭。
2. 快速连续修改左右长按动作、组合和多个手势，另一耳及其他手势不会被覆盖。
3. 触控总开关快速关开，耳缘音量原本开、关两种情况下均能正确恢复。
4. ACK 迟到或缺失时，显示目标与设备确认的区别符合上述策略；重连以设备状态为准。
5. 卡片标题、开关、菜单布局及状态刷新正常；其他品牌的风噪和游戏模式卡片保持正常。
6. 厂商 App 启停、退避和恢复正常，“停止厂商应用”覆盖对应型号插件。

HyperEars 设置 → 调试中开启“详细日志”；LSPosed 关闭“禁用详细日志”并开启
“输出日志到守护进程”。复现后使用 HyperEars 的“导出日志”保存记录。
