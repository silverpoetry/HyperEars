# Sennheiser MOMENTUM 4 / ACCENTUM GAIA 协议适配

HyperEars 为 Sennheiser MOMENTUM 4 与 ACCENTUM 系列头戴实现接入 MiLink 所需的最小
Qualcomm GAIA V3 子集：整机电量，以及在合法状态响应确认后的降噪、关闭、通透、抗风噪
四态控制。

## 1. 证据边界

| 证据 | 当前结论 |
|---|---|
| 协议族 | Qualcomm GAIA V3，Sennheiser vendor ID `0x0495`；框架层与 Qualcomm 官方 GAIA 一致 |
| 传输 | RFCOMM/SPP，SDP UUID `a2129ff3-081b-4c45-8afe-469d9c4842ec` |
| 命令表来源 | 实机抓包向量（见第 5 节），已固化为 `protocol/src/test` 下的单元测试 |
| HyperEars 实机验证 | MOMENTUM 4 已完成：精确匹配、头戴形态、私有通道连接、协议确认、私有整机电量（50%）与四态列表均正常；ACCENTUM 系列尚无设备，按“参考协议”记录 |

本次记录不包含完整个人设备 MAC。地址示例只使用合成值。

私有能力全部延迟开放：Adapter 初始匹配只选择候选，不声明私有电量、噪声模式或专用卡片。
只有收到合法的 GAIA 响应后，对应能力才逐个解锁。这与项目设计规则第 4 条一致。

## 2. 判型与传输

Adapter 只选择规范化名称命中的标准耳机，且排除 HyperOS 原生接管设备与 `LE_` 前缀的重复
广播身份：

- `sennheiser-momentum-4`：名称标记 `momentum4`，头戴形态，组合模式方言，支持抗风噪；
- `sennheiser-accentum-tws`：名称标记 `accentumtws`、`accentumtruewireless`，TWS 形态，双开关方言；
- `sennheiser-accentum`：名称标记 `accentum`，头戴形态，双开关方言；
- 品牌家族兜底：名称包含 `sennheiser`、`momentum` 或 `accentum`。

配置顺序即匹配优先级：具体型号先于家族兜底，`accentum-tws` 先于 `accentum`，否则
`ACCENTUM True Wireless` 会被更宽的 `accentum` 标记抢先命中。

服务 UUID 只定义连接端点，不能单独把其他设备判定为 Sennheiser。仅命中 GAIA UUID 的未知
设备不进入这个家族 Adapter。

HyperEars 让 Android 通过 SDP 为 UUID 解析 RFCOMM channel，不固定通道号。**channel 14 在
MOMENTUM 4 上属于 iAP2，向其发送 GAIA 帧会导致耳机关机**，因此代码中不存在任何 channel
常量，也不提供手动回退。

## 3. GAIA 帧

帧直接承载在 RFCOMM 字节流中，头部固定 8 字节，多字节字段为大端：

| 偏移 | 长度 | 含义 |
|---|---|---|
| 0 | 1 | 帧起始标志 `0xFF` |
| 1 | 1 | 协议版本与标志，固定 `0x03`（GAIA V3） |
| 2 | 2 | 载荷长度（不含头部） |
| 4 | 2 | 厂商 ID |
| 6 | 2 | 命令 ID，高 2 位为帧类型 |

命令 ID 的类型位为 `(commandId shr 7) and 0x03`：

| 类型 | 值 | 说明 |
|---|---|---|
| COMMAND | 0 | 主机发起 |
| NOTIFICATION | 1 | 设备主动上报 |
| RESPONSE | 2 | 对 COMMAND 的应答 |
| ERROR | 3 | 对 COMMAND 的错误应答 |

因此同一条业务命令在四个方向上的编码不同：以 ANC 开关为例，SET 是 `0x1A04`，GET 是
`0x1A05`，RESPONSE 是 `0x1B05`，NOTIFICATION 是 `0x1A85`。解析端按
`commandId and 0xFE7F` 还原业务命令号，再按类型位分流。

载荷上限 512 字节。读取端遇到超长长度字段时丢弃 1 字节重新同步；末尾单独的 `0xFF`
保留到下一次读取，避免把下一帧的起始标志吞掉。

## 4. 命令表

厂商 ID 为 `0x0495`（Sennheiser）；Qualcomm core API 版本查询使用 `0x001D`。

| 功能 | SET | GET | RESPONSE | NOTIFICATION |
|---|---|---|---|---|
| 组合噪声模式 | `0x1A00`，载荷 `[mode, state]` | `0x1A01` | `0x1B01` | `0x1A81` |
| ANC 开关 | `0x1A04`，载荷 `[0/1]` | `0x1A05` | `0x1B05` | `0x1A85` |
| 通透开关 | `0x1804`，载荷 `[0/1]` | `0x1805` | `0x1905` | `0x1885` |
| 通透等级 0–100 | `0x1A02` | `0x1A03` | `0x1B03` | `0x1A83` |
| 电量百分比 | — | `0x0603` | `0x0703`，载荷 1 字节 | `0x0683` |
| 型号字符串 | — | `0x1206` | `0x1306`，ASCII 含 `\0` | — |
| 注册通知 | INVOKE `0x0007`，载荷 `[featureId]` | — | `0x0107` | — |
| Qualcomm core API 版本 | — | vendor `0x001D`，命令 `0x0000` | `0x0100` | — |

注册通知使用 feature ID：电量 `3`、通透 `12`、ANC `13`。MOMENTUM 4 的 core API 版本响应
为 `03 01`。

通透等级、均衡器、手势、固件升级和配对管理不在本次范围内。

## 5. 抓包向量

以下向量已固化为单元测试，同时作为实现与设备行为之间的对照基准：

| 操作 | 发送 | 接收 |
|---|---|---|
| 读电量 | `FF 03 00 00 04 95 06 03` | `FF 03 00 01 04 95 07 03 2A`（42%） |
| 读组合模式 | `FF 03 00 00 04 95 1A 01` | `FF 03 00 06 04 95 1B 01 01 02 02 00 03 01` |
| 读型号 | `FF 03 00 00 04 95 12 06` | `FF 03 00 0D 04 95 13 06 "MMMMBT Black\0"` |
| 开 ANC | `FF 03 00 01 04 95 1A 04 01` | `FF 03 00 01 04 95 1B 04 01` + 通知 `FF 03 00 01 04 95 1A 85 01` |

## 6. 噪声四态

### 6.1 组合模式方言（MOMENTUM 4）

`0x1A01` 回读载荷固定为 6 字节，三个 `[mode, state]` 对：

| 选择器 | mode 值 |
|---|---|
| 通透 | `2` |
| 抗风噪 | `1` |
| 自适应降噪 | `3` |

四态由唯一投影得出，顺序不可交换：

1. 通透 `state != 0` → 通透；
2. 否则抗风噪 `state != 0` → 抗风噪；
3. 否则自适应降噪 `state != 0` → 降噪；
4. 否则关闭。

写入方向按目标状态逐个选择器下发：

| 目标 | 写入序列 |
|---|---|
| 降噪 | `1A00 [03 01]`、`1A00 [02 00]`、`1A00 [01 00]` |
| 通透 | `1A00 [02 01]`、`1A00 [03 00]`、`1A00 [01 00]` |
| 抗风噪 | `1A00 [03 01]`、`1A00 [01 01]` |
| 关闭 | `1A00 [03 00]`、`1A00 [02 00]`、`1A00 [01 00]` |

抗风噪在设备上以自适应降噪为前提，因此写入前先置 `mode 3`。回读只使用 `0x1A01` 一条命令，
不追加通知注册。

### 6.2 双开关方言（ACCENTUM / ACCENTUM True Wireless）

两个独立开关，`0x1A05` 与 `0x1805` 分别回读：

| 目标 | 写入序列 |
|---|---|
| 降噪 | `1A04 [01]`、`1804 [00]` |
| 通透 | `1804 [01]`、`1A04 [00]` |
| 关闭 | `1A04 [00]`、`1804 [00]` |

该方言不声明抗风噪能力，因此 `windNoiseControl` 保持 false，MiLink 抗风噪开关不出现。
两个开关都收到合法回读后才发布模式；只收到其中一个时保持等待，不猜测另一侧状态。

## 7. 能力确认

Adapter 在握手阶段发送的电量、组合模式、型号与 core API 版本查询各自独立确认：

- 合法电量响应（1 字节，0–100）→ 电量源从系统整机切换为私有整机；
- 合法组合模式响应（恰好 6 字节）→ 开放四态（组合方言）或三态（双开关方言）；
- 型号字符串响应 → 仅记录身份，不开放能力；
- core API 版本响应 → 仅证明 GAIA 通道可用，不开放能力。

任一响应解析失败时按未知帧处理，不影响其他能力已获得的确认。协议重置后撤销全部私有证据，
电量源回到系统整机。

## 8. MiLink 卡片

MOMENTUM 4 使用 `sennheiser-momentum-4` 作为卡片 presentation ID，绑定原生 ANC 宿主并追加
抗风噪开关。抗风噪开关的可用性直接取自 `windNoiseControl` 能力，只在已确认为降噪或抗风噪
分支时可操作。

ACCENTUM 与 ACCENTUM True Wireless 不注册专用卡片，使用宿主原生三态界面。
