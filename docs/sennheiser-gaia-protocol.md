# Sennheiser MOMENTUM 4 / ACCENTUM GAIA 协议适配

本维护分支为 Sennheiser MOMENTUM 4、ACCENTUM 与 ACCENTUM True Wireless 实现接入 MiLink
所需的 Qualcomm GAIA V3 子集：整机电量及三态噪声控制；MOMENTUM 4 另支持抗风噪。
私有能力均由对应合法状态响应确认。原 PR #122 的 MOMENTUM 4 已有实测，维护版待最终实机复核。

## 1. 证据边界

| 证据 | 当前结论 |
|---|---|
| 协议族 | Qualcomm GAIA V3，Sennheiser vendor ID `0x0495`；框架层与 Qualcomm 官方 GAIA 一致 |
| 传输 | RFCOMM/SPP，SDP UUID `a2129ff3-081b-4c45-8afe-469d9c4842ec` |
| 命令表来源 | 实机抓包向量（见第 5 节）与四个独立公开实现的交叉核对（见第 10 节），已固化为 `protocol/src/test` 下的单元测试 |
| 原 PR 实机验证 | #122 作者报告 MOMENTUM 4 识别、连接、整机电量及四态控制正常；ACCENTUM 系列按参考协议记录 |
| 维护版验证 | 修正双开关投影、写入副作用及确认条件后，定向单元测试通过；最终维护包待设备复核 |

本次记录不包含完整个人设备 MAC。地址示例只使用合成值。

私有能力全部延迟开放：Adapter 初始匹配只选择候选，不声明私有电量、噪声模式或专用卡片。
只有收到合法的 GAIA 响应后，对应能力才逐个解锁。这与项目设计规则第 4 条一致。

## 2. 判型与传输

Adapter 只选择规范化名称命中的标准耳机，且排除 HyperOS 原生接管设备与 `LE_` 前缀的重复
广播身份：

- `sennheiser-momentum-4`：完整名称 `momentum4`、`momentum4wireless`，头戴形态，支持抗风噪；
- `sennheiser-accentum-tws`：名称标记 `accentumtws`、`accentumtruewireless`，TWS 形态，ACCENTUM 方言；
- `sennheiser-accentum`：完整名称 `accentum`、`accentumwireless`，头戴形态，ACCENTUM 方言；
- 品牌家族兜底：名称包含 `sennheiser`、`momentum` 或 `accentum`。

以上型号名允许 `sennheiser` 品牌前缀。具体型号按规范化完整名称匹配；ACCENTUM Plus、Open
等其他名称保留标准家族回退，不从已知型号外推私有方言。未知家族不发 GAIA 探测命令。

服务 UUID 只定义连接端点，不能单独把其他设备判定为 Sennheiser。仅命中 GAIA UUID 的未知
设备不进入这个家族 Adapter。

HyperEars 让 Android 通过 SDP 为 UUID 解析 RFCOMM channel，不固定通道号。**channel 14 在
MOMENTUM 4 上属于 iAP2，向其发送 GAIA 帧会导致耳机关机**，因此代码中不存在任何 channel
常量，也不提供手动回退。

## 3. GAIA 帧

帧直接承载在 RFCOMM 字节流中，头部固定 8 字节，多字节字段为大端：

| 偏移 | 长度 | 含义 |
|---|---|---|
| 0 | 1 | 帧起始标志 `0xFF` |
| 1 | 1 | 协议版本与标志，固定 `0x03`（GAIA V3） |
| 2 | 2 | 载荷长度（不含头部） |
| 4 | 2 | 厂商 ID |
| 6 | 2 | 命令 ID，第 7–8 位为帧类型 |

命令 ID 的类型位为 `(commandId shr 7) and 0x03`：

| 类型 | 值 | 说明 |
|---|---|---|
| COMMAND | 0 | 主机发起 |
| NOTIFICATION | 1 | 设备主动上报 |
| RESPONSE | 2 | 对 COMMAND 的应答 |
| ERROR | 3 | 对 COMMAND 的错误应答 |

因此同一条业务命令在四个方向上的编码不同：以 ANC 开关为例，SET 是 `0x1A04`，GET 是
`0x1A05`，RESPONSE 是 `0x1B05`，NOTIFICATION 是 `0x1A85`。解析端按
`commandId and 0xFE7F` 还原业务命令号，再按类型位分流。

载荷上限 512 字节。读取端遇到超长长度字段时丢弃 1 字节重新同步；末尾单独的 `0xFF`
保留到下一次读取，避免把下一帧的起始标志吞掉。

## 4. 命令表

厂商 ID 为 `0x0495`（Sennheiser）；Qualcomm core API 版本查询使用 `0x001D`。

| 功能 | SET | GET | RESPONSE | NOTIFICATION |
|---|---|---|---|---|
| 子模式表 | `0x1A00`，载荷 `[mode, state]` | `0x1A01` | `0x1B01` | `0x1A81` |
| ANC 主开关 | `0x1A04`，载荷 `[0/1]` | `0x1A05` | `0x1B05` | `0x1A85` |
| 通透开关 | `0x1804`，载荷 `[0/1]` | `0x1805` | `0x1905` | `0x1885` |
| 通透等级 0–100 | `0x1A02` | `0x1A03` | `0x1B03` | `0x1A83` |
| 电量百分比 | — | `0x0603` | `0x0703`，载荷 1 字节 | `0x0683` |
| 型号字符串 | — | `0x1206` | `0x1306`，ASCII 含 `\0` | — |
| 注册通知 | INVOKE `0x0007`，载荷 `[featureId]` | — | `0x0107` | — |
| Qualcomm core API 版本 | — | vendor `0x001D`，命令 `0x0000` | `0x0100` | — |

注册通知使用 feature ID：电量 `3`、通透 `12`、ANC `13`。MOMENTUM 4 的 core API 版本响应
为 `03 01`。

通透等级、均衡器、手势、固件升级和配对管理不在本次范围内。

## 5. 抓包向量

以下向量已固化为单元测试，同时作为实现与设备行为之间的对照基准：

| 操作 | 发送 | 接收 |
|---|---|---|
| 读电量 | `FF 03 00 00 04 95 06 03` | `FF 03 00 01 04 95 07 03 2A`（42%） |
| 读子模式表 | `FF 03 00 00 04 95 1A 01` | `FF 03 00 06 04 95 1B 01 01 02 02 00 03 01` |
| 读型号 | `FF 03 00 00 04 95 12 06` | `FF 03 00 0D 04 95 13 06 "MMMMBT Black\0"` |
| 开 ANC | `FF 03 00 01 04 95 1A 04 01` | `FF 03 00 01 04 95 1B 04 01` + 通知 `FF 03 00 01 04 95 1A 85 01` |

子模式表回读的 6 字节按 `[mode, state]` 对解读，不能按序号读：`01 02 02 00 03 01` 是
「抗风噪 `2`（自动）、舒适 `0`、自适应降噪 `1`」。

## 6. 噪声四态

四态由两个主开关加一个子模式表共同决定。**`0x1A00` 不是主模式开关**：它只调三个叠加在
主开关之上的子行为，单写它永远离不开直通态。

| 命令 | 作用 |
|---|---|
| `0x1A04` | ANC 主开关。开时同时结束通透并把通透等级置 0 |
| `0x1804` | 通透开关。开时等级置 100，关时恢复到之前记忆的值 |
| `0x1A00` | 子模式表，`[mode, state]` 对 |

`0x1A00` 的 `mode` 取值：

| 选择器 | mode 值 | state 取值 |
|---|---|---|
| 抗风噪 | `1` | `0` 关、`1` 最大、`2` 自动 |
| 舒适（Comfort） | `2` | `0` / `1` |
| 自适应降噪 | `3` | `0` / `1` |

`mode 2` 是 Comfort，**不是通透**；通透有自己的 `0x1804` 命令。写 `0x1A00` 有强制副作用：
即使写入相同值，也会结束通透（`0x1805` 归 0）并把等级置 0。

### 6.1 MOMENTUM 4

主开关开着且无子选择器激活时，耳机处于直通态，听感与通透相同。因此「关闭」必须关主开关，
而不能只清子模式表：

| 目标 | 完整写入序列（无缓存时的保守序列） |
|---|---|
| 降噪 | `1A04 [01]`、`1804 [00]`、必要时 `1A00 [01 00]` 清除抗风噪 |
| 通透 | `1A04 [01]`、`1804 [01]` |
| 抗风噪 | `1A04 [01]`、`1804 [00]`、`1A00 [01 02]` |
| 关闭 | `1A04 [00]` |

关闭后通透开关形式上仍为 `1`，但 ANC 关着时不产生效果。**不要补写 `1804 [00]`**：那会丢弃
耳机记忆的通透等级前值。

开主开关会结束通透，所以通透必须先开主开关再开通透开关，顺序不可交换。

上表只是保守序列。实际写入按已观测状态做差异计算，每条命令只在它真的会改变设备时才发出：

- 降噪：主开关未开才写 `1A04 [01]`（开主开关本身会结束通透）；主开关已开且通透仍为开时补
  `1804 [00]`；抗风噪选择器非 `0` 或未知时补 `1A00 [01 00]` 清除残留。
- 通透：主开关未开时先写 `1A04 [01]`，随后必须写 `1804 [01]`，因为前一条会清除通透；
  主开关已经开启时，仅在通透未开时补写通透命令。
- 抗风噪：主开关未开才写 `1A04 [01]`；随后若主开关、通透、选择器三者尚未同时到位，写一条
  `1A00 [01 02]`——该写入自带结束通透的副作用，因此一条即完成整个切换。
- 关闭：只写 `1A04 [00]`。残留的抗风噪选择器被主开关遮蔽，留给下一次进入降噪时清除。

耳机会为每条被接受的写入播一次确认音，所以写入条数直接决定提示音次数。差异计算在设备已处
于目标态时会算出空列表，而运行时把空列表判为控制失败，因此每种目标都保留一条主写入作为退化
兜底。

状态投影按以下优先级，且必须先拿到主开关、通透及合法抗风噪选择器三个回读：

1. ANC 主开关 `0` → 关闭；
2. 否则通透开关 `1` → 通透；
3. 否则抗风噪选择器 `!= 0` → 抗风噪；
4. 否则 → 降噪。

回读使用 `0x1A05`、`0x1805`、`0x1A01` 三条命令，并注册 ANC（`13`）与通透（`12`）两个通知。
状态查询只回读这三条，不重复注册通知。

一次模式切换是多条独立写入，耳机会在每条写入落地时各推一条通知，中间必然出现既非源态也非
目标态的过渡值。因此写入后即按请求的模式乐观发布，并对后续模式报告启用有界的延迟抑制：
报告与请求模式不符时暂不发布，而是安排一次延后重读；三档延迟（150 ms、300 ms、500 ms）用尽
后强制接受设备报告，保证抑制一定收敛。抑制只在存在待确认请求时生效，设备主动发起的报告直接
透传。

### 6.2 ACCENTUM / ACCENTUM True Wireless

两个独立开关，`0x1A05` 与 `0x1805` 分别回读：

| 目标 | 完整写入序列 |
|---|---|
| 降噪 | `1A04 [01]`、`1804 [00]` |
| 通透 | `1804 [01]`、`1A04 [00]` |
| 关闭 | `1A04 [00]`、`1804 [00]` |

该方言不声明抗风噪能力，因此 `windNoiseControl` 保持 false，MiLink 抗风噪开关不出现。
两个开关都收到合法回读后才发布模式；通透为开时优先投影通透，否则按 ANC 开关投影降噪或关闭。
这与 MOMENTUM 4 的主开关依赖不同。只收到其中一个时保持等待；写入按已观测状态做差异计算。

## 7. 能力确认

握手先查询 Qualcomm core API，合法响应后读取电量、主开关及需要的子模式表并注册通知：

- 合法电量响应（1 字节，0–100）→ 电量源从系统整机切换为私有整机；
- 合法的 ANC 与通透开关响应（各 1 字节，只接受 0/1）→ ACCENTUM 开放三态；
- MOMENTUM 4 还需子模式表中唯一且合法的抗风噪值（0/1/2）→ 开放四态；
- 合法型号字符串响应 → 只确认协议可应答，不改变匹配身份或开放能力；
- core API 版本响应 → 仅证明 GAIA 通道可用，不开放能力。

Qualcomm core 与 Sennheiser 业务命令分别校验 vendor ID。其他厂商、空载荷、非法开关值或错误应答
不能确认握手。任一响应解析失败时按未知帧处理，不影响其他能力已获得的确认。协议重置后撤销全部私有证据，
电量源回到系统整机。

## 8. MiLink 卡片

MOMENTUM 4 使用 `sennheiser-momentum-4` 作为卡片 presentation ID，绑定原生 ANC 宿主并追加
抗风噪开关。抗风噪开关的可用性直接取自 `windNoiseControl` 能力，只在已确认为降噪或抗风噪
分支时可操作。

ACCENTUM 与 ACCENTUM True Wireless 不注册专用卡片，使用宿主原生三态界面。

## 9. 实机验证记录

2026-11-02，#122 作者使用原 PR 构建的 release APK 在 MOMENTUM 4 上完成验证，报告正常：

| 项目 | 结果 |
|---|---|
| 身份 | 精确匹配，Adapter `sennheiser-momentum-4`，形态识别为头戴 |
| 私有传输 | RFCOMM 经 SDP 解析 GAIA UUID 后连接成功，协议握手确认 |
| 电量 | 私有整机 50%，未出现左右耳或充电盒字段 |
| 噪声模式 | 降噪、关闭、通透、抗风噪四项全部出现；当前态正确显示为关闭 |
| MiLink | 状态接收、身份查询、卡片能力查询与状态通知均完成 |

首轮实机验证发现「关闭」与「通透」听感相同。原因在第 6.1 节已记录：早期实现只写 `0x1A00`
子模式表，从未驱动 `0x1A04` 主开关，两个目标都落到「主开关开着但无子选择器激活」的直通态。

第二轮实机验证反馈两点：切换模式时会响两次提示音，四个状态显示混乱。根因与修法：

| 现象 | 根因 | 修法 |
|---|---|---|
| 切换响两次提示音 | 写入序列与当前状态无关，每次都发满固定几条帧，其中包含大量值未变的冗余写入 | 按已观测状态做差异计算，每条命令只在真的会改变设备时才发 |
| 点降噪显示抗风噪 | 抗风噪选择器只增不清，用过抗风噪后投影恒判为抗风噪 | 进入降噪时按需写 `1A00 [01 00]` 清除残留；协议重置同时清空缓存的选择器 |
| 切换瞬间闪出没点过的状态 | 多帧写入各触发一条通知，中间态直接漏到界面 | 写入后乐观发布请求模式，并对后续模式报告启用有界延迟抑制 |
| 抗风噪切回降噪后界面完全不动 | 两帧写入值全部未变，设备不推通知，本地缓存的选择器仍是旧值 | 同一处差异计算 + 清除残留选择器 |

仍待实机确认的三项：设备对同值写入是否仍推通知；主开关关闭是否清空抗风噪选择器；提示音是否
按每条被接受的写入各响一次。
改用主开关方案后重新验证，四态切换均正常。

仍待验证：

1. ACCENTUM 与 ACCENTUM True Wireless 的双开关方言（第 6.2 节）——尚无对应设备；
2. 抗风噪是否在所有固件版本上都要求自适应降噪同时开启；
3. 断开重连后 GAIA 通道的恢复时间。

验证方式见 [`CONTRIBUTING.md`](../CONTRIBUTING.md) 的设备证据章节。
