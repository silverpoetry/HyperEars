# Sony Headphones 协议适配

## 范围

HyperEars 实现 Sony Headphones Connect 私有 RFCOMM 协议及经会话能力发现确认的日常设置：

- Sony 私有 v1 服务 `96cc203e-5068-46ad-b32d-e316f5e069ba`；
- Sony 私有 v2 服务 `956c7b26-d49a-4ba8-b03f-b17d393cb6e2`；
- 初始化、序号和 ACK 请求队列；
- 单整机、双耳和充电盒电量；
- 降噪、关闭、环境声，以及已登记型号的抗风噪状态；
- 2026 代型号（WF-1000XM6）的 v2 环境声方言：子类型 `0x19`，通知帧负载为
  `69 19 <00> <开关> <降噪/环境声> <00> <等级> <00> <00>`，开关与模式字节位置与
  `0x15` 方言一致；写入帧第三字节为切换确认提示音标志（Sound Connect 实测为 `0x01`，
  静默拖拽为 `0x00`），完整写入为
  `68 19 01 <开关> <降噪/环境声> 00 14 00 00`。

新增 EQ 预设、设备端频段编辑、Clear Bass、环境声等级和关注语音。触控分配、语音助手、
固件升级及新的 GATT 通道仍不在本批范围，不依据型号名称开放高级功能。

## 帧与生命周期

消息以 `0x3e` 开始、`0x3c` 结束。消息类型、序号、四字节大端负载长度、负载和累加
校验位于帧内；`0x3c`、`0x3d`、`0x3e` 使用 `0x3d` 转义。连接建立后只发送初始化
请求 `00 00`。初始化响应长度为 4 时使用 v1，为 8 时使用 v2。

部分 v1 固件（WH-1000XM4，已实机验证）会忽略第一帧初始化请求，只在重发后才返回
初始化响应。该精确型号在握手完成前收到设备命令时最多重发一次 `00 00`，与已捕获的
Sound Connect 行为一致；相邻型号和 Sony 家族候选保持零重试，通用握手时限不变。

Sony 通道一次只允许一个等待 ACK 的请求。HyperEars 的协议实例维护设备序号和请求
队列：收到设备命令后立即回 ACK，收到上一请求的 ACK 后才发送下一项。Socket、协程、
重连和 MiLink 发布仍由通用设备会话管理，协议对象不持有系统资源。ACK 队列忙时新控制请求会被拒绝且不入队，避免框架返回拒绝后
又在稍后的 ACK 中执行该写入；队列排空后重试可以接受。高级弹层仍保留回报真值，并在
未确认时提示重试，不自动重发控制。

## 适配层级

1. `SonyEarbudAdapter`：只提供标准 A2DP/HFP、流转、音量和 Android 整机电量回退；
2. `SonyProtocolFamilyAdapter`：声明 Sony RFCOMM、握手、ACK 队列和 v1/v2 公共语义；
3. 具体型号 Adapter：内嵌 `SonyAdapterConfig`，声明外形、电池拓扑、环境声方言和
   服务优先级。

已登记 Adapter 覆盖 WH-1000XM2–XM6、WH-CH720N、ULT WEAR、WF-1000XM3–XM6、
WF-C500/C510/C700N/C710N、WF-SP800N、WI-SP600N、WI-C100、LinkBuds 和
LinkBuds S。未知 `WH/WI/MDR` 或 `WF/LinkBuds` 产品先进入协议家族；名称明确表示降噪
产品时开放通用三态，否则只读取协议电量。未知型号仍须返回合法初始化帧，私有通道
才会就绪；合法电量或环境声状态响应分别确认对应能力，名称本身不会提前开放控制。

## 动态日常设置

初始化完成后在现有电量／噪声查询之后发送一次 `06 00` 支持功能查询；没有新增轮询。
`07` 回报在 V1 中包含单字节功能列表，在 V2 中包含功能编号与排序的二字节对，严格校验
计数和完整长度。只对声明过的已知功能查询参数；重复相同声明不重复扩张查询队列。

RFCOMM 外层 `0x0C` 是 Table 1，`0x0E` 是 Table 2；SonyPods 的内部 `0x0F` 标记由 SPP
映射为外层 `0x0E`。Table 2 的同号命令只被应答，不进入 Table 1 的 EQ、电量和环境声解析。
本批没有把 Table 2 的 safe-listening `0x51` 当成 EQ capability。

EQ 功能编号在 V1 为 `51/52/53`，分别对应查询类型 `01/02/03`；V2 使用声明的
`50/51/52/53/55/57`，分别对应 `00/01/02/03/31/04`。状态 `53/55`、参数 `57/59` 与
扩展几何 `5B` 分别验证，状态不允许、参数缺失或几何不完整时相应写入保持关闭。
不把 ACK 当作参数确认，不把未知值变成默认预设。

- 标准 EQ 步进为 raw `0..20`，中心 `10`；十个频率段且没有 Clear Bass 槽时使用
  raw `0..12`，中心 `6`。频率来自完整 `5B` 回报的 Hz/kHz 几何。
- Clear Bass 的 specific-information 槽必须位于数组首项；此路径重发完整频段并保留
  其他频段。独立 EBB 需要自己的参数和启用状态，十段 EQ 不虚构 Clear Bass。
- V1 自定义频段使用 `58 01 FF count steps...`；V2 CUSTOM_EQ `31` 没有预设字段。
  ULT 参数类型 `03` 保留独立 ULT 状态，不把 ULT 应用层标签误写成普通预设字节。
- 所有设置的写入和读取确认按现有 ACK 队列顺序执行，发送后不乐观发布新状态。

环境声类型来自设备功能列表。合法参数回报决定等级和关注语音是否可编辑；V2 的
`14/17/19` 提供独立语音关注控制，其他布局保留已有语音字节。多布局同时回报时优先已确认
的 dual 布局，避免把 AUTO 布局写入设备的 dual 路径。编辑只修改当前合法布局中的等级和
语音字段，保留模式、风噪和自适应相关字节；自适应环境声开启时暂停手动编辑。
合法关闭／降噪回报中的等级 `0` 会更新当前模式并隐藏编辑器；关闭／降噪写入保留当前零值
及语音、自适应等字段，不回退到丢失字段的旧模板。显式切到环境声时优先重用本会话已回报的
正等级；从未回报正等级时按照上游 `setNoiseControlMode` 明确写入默认目标 `10`。该目标不
作为观测状态发布，仍等待设备回报。此默认目标见
[SonyHeadphoneRepository.kt:1866–1888](https://github.com/Mercury000/SonyPods/blob/3f701ff8f9b30c6909b9dbe8d99248f20d55560e/app/src/main/java/dev/sonypods/data/SonyHeadphoneRepository.kt#L1866-L1888)。

MiLink 使用宿主原生模式控件及高级设置入口；没有噪声能力时提供仅设置入口，WF-C510
不出现降噪选项。EQ 频段采用明确草稿和“应用”操作，请求携带完整类型化定义（协议版本、参数类型、频段几何、
步进中心及 ULT 状态），Adapter 和 ProtocolSession 均检查定义仍然匹配，阻止 IPC 延迟导致
相同频段数量的旧草稿写入另一布局。已知几何发生变化时撤回旧参数投影，每次实际变化只追加
一条 `56` 参数查询；首次几何到达不丢弃已收到的参数，相同几何重复回报不追加查询。
应用时合并最新 Clear Bass，避免
覆盖在另一控件刚刚改变的低音值。不是手机端软件 EQ。弹层观察当前会话，断连、控制权交接、
会话令牌变化及解绑时释放监听与 UI 超时任务。新批次高级设置仍待最终版本设备复核。

## 证据与限制

协议帧依据公开协议文档、SonyHeadphonesClient 和 Gadgetbridge 的可互操作行为独立
实现。上述型号当前属于公开实现画像，尚未完成 HyperEars 本地逐型号实机验证；
WF-1000XM6 的 v2 握手、双耳与充电盒电量、`0x19` 环境声通知解析和三态写入，以及
WH-1000XM4 的 v1 握手重发、整机电量、`0x02` 环境声方言和模式写入均已依据真实设备
流量验证；XM4 的握手行为和 XM6 的确认音标志均与 Sound Connect 抓包一致。型号名用于
选择候选 Adapter 配置，Sony 私有 RFCOMM 初始化响应用于确认协议和家族能力；公共 iAP2
accessory UUID 不参与 Sony 品牌判型；`LE_` 广播影子名称不会创建第二个设备会话。

完整来源、固定提交和许可证见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。

## DSEE、连接质量和 Speak-to-Chat

此切片依据 SonyPods 固定提交 `3f701ff8f9b30c6909b9dbe8d99248f20d55560e`，
`SonyFunctionType.kt`、`SonyCapabilityProbe.kt`、`SonyTandemV1Table1Protocol.kt`、
`SonyTandemV2Table1Protocol.kt` 及对应协议单元测试。它们是来源实现与固定样本证据，
不是本切片已完成 HyperEars 实机验收的证明。

- DSEE 只在 V2 Table1 开放：支持函数 `E2` 选择 AUDIO 查询类型 `01`，`ED` 选择 `0B`，
  同时报出时优先 `01`。`E0/E1 [type,generation]` 回报 HX/DSEE/Extreme/Ultimate 的 `0..3`；
  `E6` 查询，`E7/E9 [type,value]` 确认开关，`E8 [type,value]` 写入，`0=关闭,1=自动`。
  `0B` 另查询 `E2`，仅 `E3/E5 [type,0=可用/1=禁用]` 开放写入；类型 `01` 由合法参数回报门控。
- 连接质量同属 V2 Table1：函数 `E7→05` 优先，其次 `E1→00`、`E3→02`。
  `E6/E7/E9` 参数回报支持 `[type,mode]` 或来源携带切换流状态的 `[type,mode,stream]`；
  `E2/E3/E5` 单独查询／确认当前可用性。`E8 [type,mode]` 只提供 `00` 音质优先、`01` 连接稳定优先。
  `05` 回报的 `02` 低延迟保留显示，不提供未经来源 UI 开放的第三个写选项。
  DSEE 与连接质量的 availability 保留查询类型，互不覆盖；GET 回显不成为状态。
- Speak-to-Chat 的 V1 函数 `F5→05`，V2 函数 `F2→02`、`FC→0C`，
  后者依来源支持函数排序选择首先出现的类型。V1 `F8 [05,01,value]` 的 `1=开,0=关`；
  V2 `F8 [type,value,01]` 的 `0=开,1=关`。`F6` 回读参数：
  V1 `F7 [05,00,value]`／`F9 [05,01,value]`，V2 `F7/F9 [type,value,01]`。
  `F2` 查询的 `F3/F5 [type,availability,effect]` 只表示可用性和正在触发的效果，
  不是开关值；状态与开关都得到合法回报后才允许写入。未知极性、预览标志和长度均拒绝。
- SonyPods 单元样本中的前导 `0E` 是它的内部 DATA_MDR 标记；此处去掉标记后进入现有
  SPP Table1 `COMMAND_1` 外层 `0C`。SPP 外层 Table2 `COMMAND_2` 的 `0E` 不参与解析，
  相同命令字节也不会跨表授予功能。V1 中仅存在同名函数枚举不代表已证明 DSEE／质量写入，故不开放。
- 新请求携带精确 `(version,inquiredType)` 定义，Adapter 与会话同时验证；支持函数改变或撤销
  会清除对应旧参数与可用性，旧 IPC 请求不能写到新类型。写入后入队一次参数／状态回读，
  沿用现有 ACK 顺序和忙时先拒绝、不暗中排队的行为，没有周期轮询或乐观成功。
- 已有 Sony 高级详情显示独立开关与两档质量选择；显示设备确认值，不可用时保留值并禁用。
  会话、地址、连接、所有权、弹层和观察者清理规则与 EQ／环境声一致。断连清除新特性。

多点开关属于 GS 能力标题 `MULTIPOINT_SETTING` 对应的动态槽位，并可能需要断连确认；
Table2 的 SOURCE_SWITCH_CONTROL 是设备管理而非该开关。佩戴检测状态也不等于摘下暂停设置。
这些流程、自动关机与动态手势映射仍需各自完整实现，不通过通用布尔值或枚举名称推测写入。
