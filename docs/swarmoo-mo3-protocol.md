# SWARMOO MO3 PRO 核心协议

## 1. 来源与验证边界

协议事实来自 [Issue #97](https://github.com/silverpoetry/HyperEars/issues/97) 的 ZaneZhang111，
以及其[补充传输资料](https://github.com/silverpoetry/HyperEars/issues/97#issuecomment-6552135643)。
维护者独立核对 2026-11-01 官方 App 抓包：两条特征均使用 ATT Write Request，错误应答后有
模式或电量通知；盒电量样本为 20%。贡献者另报告测试程序可读到 22%、19% 及完整状态帧。

材料对应系统名 SWARMOO MO3，固件 `BTFW.BRAHMA.2.0.1-00339-PATCHZ-1.164416.3_DEF`。
这些事实支持制作维护版；原测试程序的成功不能代替 HyperEars 最终维护包的实机复核。
实现独立编写，只使用协议事实，不复制附件应用代码，不分发抓包原件或厂商资源。

范围为电量、标准噪声模式和抗风噪。自适应降噪归入标准降噪，EQ、手势、固件等交给
轻链智能 `com.example.tigerlistening`，沿用现有导航与运行时退避。

## 2. 身份与端点

仅规范化完整名称 `SWARMOO MO3` / `SWARMOO MO3 PRO` 选择私有候选；要求标准耳机身份并
排除系统原生设备。其他 SWARMOO 使用标准家族。FFF0 和 2A19 是共享 UUID，不能单独确定品牌。

同一 GATT 连接、服务 `0000fff0-0000-1000-8000-00805f9b34fb` 内：

| 逻辑通道 | 写与通知特征 | 属性 | 查询 |
|---|---|---|---|
| 主通道（模式） | `0000ffa1-0000-1000-8000-00805f9b34fb` | Write + Notify | `55 AA 0A 00 FF` |
| battery（电量） | `00002a19-0000-1000-8000-00805f9b34fb` | Write + Notify | 同上 |

2A19 在私有 FFF0 下，按私有通知处理；不执行标准 BAS Read。只解析声明的这两条特征，
依次订阅 CCCD，不扫描其他可写特征，不访问 FFA2 / FF12。未发现必需端点或订阅失败则结束候选。

23 字节状态通知要求 ATT MTU 至少 26。仅该端点声明最低 MTU，协商成功且达到要求才继续服务发现。
Android 14 起请求可能统一为 517，代码检查实际回调值，不要求恰好 26 或 247；依据
[Android requestMtu 文档](https://developer.android.com/reference/android/bluetooth/BluetoothGatt#requestMtu(int))。
失败或低于最低值时不接受 20 字节截断帧。

## 3. 读写帧

| 用途 | 帧 | 语义 |
|---|---|---|
| 状态查询 | `55 AA 0A 00 FF` | 依次发给模式与电量特征 |
| 主模式 | `55 AA 0A 01 xx` | 0 关闭，1 降噪，2 通透 |
| 降噪子档 | `55 AA 0A 02 xx` | 1 抗风噪，2 自适应；没有子档 0 的写入证据 |
| 模式通知 | `55 AA 0B 00 …`，严格 23 字节 | 偏移 5 主模式，6 子档，均只接受 0–2 |
| 电量通知 | `55 AA 0B 00 L R C`，严格 7 字节 | 左右耳 0–100，255 未知；盒 1–100，0/255 未知 |

完整模式样本：`55 AA 0B 00 00 01 02 00 00 00 00 00 01 FF 09 01 00 FF FF FF 01 00 00`。
电量样本：`55 AA 0B 00 64 64 14`，即 100/100/20%。未知字段不解释成额外功能。
来自模式特征的短帧不能冒充电量；接收时保留通知边界与逻辑通道，不跨特征拼接。

电量与模式分别确认。模式 0 投影关闭、2 投影通透、1 + 子档 1 投影抗风噪，其余合法降噪子档
投影降噪。标准降噪写入主模式 1 + 子档 2；抗风噪写入主模式 1 + 子档 1。主模式与子档
互不替代，所以这两个目标各用两帧；关闭、通透各用一帧。

盒 0 尚不能区分零电与未检测，保持未知并清除旧值。没有充电标志证据，不显示充电中。
电量能力确认后，完整未知报告仍替换旧组件快照；首次全未知报告不会撤销系统整机回退。

## 4. 异常应答与状态确认

抓包确认模式、电量写请求会返回 ATT Invalid Handle（状态 1），随后仍有有效协议通知。
此例外只在 MO3 Adapter、声明的通道和已知命令生效；记录原错误，继续等协议回报，不重发控制。
其他状态码、提交失败、超时、断连和 CCCD 失败照常失败。没有全局忽略错误或切无响应写的兜底。

控制使用 `DEVICE_REPORT`，不乐观修改模式；传输报错被容许继续等待也不代表控制成功。
写后回读不符合目标时，Adapter 用既有事件接口 HOLD，并按 250/500/700ms 有界安排状态查询。
目标回报到达或三次仍不一致时接受真实设备状态。没有回报时保留原状态，不伪造目标状态。

## 5. 生命周期与共享改动

匹配阶段不发包。标准连接后建立一个 GATT 会话，所有写入至少间隔 300ms；同一查询分别发到
两个声明通道。初始查询、手动刷新、卡片刷新及有限写后回读之外没有持续轮询。

`GattTransportSpec` 的附加路由和最低 MTU 均为可选项；其他型号保留原单通道与平台 MTU。
`ProtocolSession` 默认只读写主通道；新增路由保留原始字节，不加入虚构帧前缀。
Android 通道只负责 MTU、订阅、路由、串行写及失败回报；模式、确认与延迟策略留在 Adapter / Session。
RFCOMM/L2CAP 保持流式读取，GATT 保留通知数据报。连接截止和握手超时未延长。

退出或厂商 App 接管时沿用统一会话清理，关闭 GATT 并取消状态请求。重连重新确认全部能力；
初始协议始终未确认则有限回退标准家族，禁用的家族按统一规则退到标准耳机。

## 6. 最终包复核

请用最终维护包确认自动匹配、完整 MTU、两特征订阅、左右耳/盒电量、四态互切、卡片重开、
断开重连以及轻链智能退避恢复。开启详细日志后保留端点、路由、MTU、原始写回包状态及合法
协议响应，导出同一次会话日志。模式切换成功需设备回报与实际效果一致。
维护版在这些结果齐备前保持 Draft，Issue #97 保持开放。
